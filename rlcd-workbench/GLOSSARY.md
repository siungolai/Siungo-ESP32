## 硬件层

**工作台**：
本项目造出来的这块设备的统称——一块 4.2 寸全反射黑白屏 + 板载两键 + 温湿度 / 电量 / 实时时钟，负责把「本地信息」与「服务器状态」摆在一块屏上。
_Avoid_: 面板屏、终端、仪表盘（会与「面板」混淆）

**面板**：
工作台上一次只显示一个的内容单元，共两个：**本地**（时间 / 日历 / 传感器 / 待办）、**服务器**（健康状况）。原定的第三个面板（AI 对话）本期连设计也不做。面板之间是**互斥**的，同一时刻只有一个在屏上。
_Avoid_: 屏幕、屏、界面、section

**页**：
面板内部的一份内容单位。**本期每个面板只有一页**（本地面板原本想分两页，已合并为一页）。「页」这个概念保留下来，是为了将来面板内部需要分页时不必改交互语义。
_Avoid_: 分页、分屏、副页

**页首**：
常驻在屏顶的一行状态条，三段式：左段日期 + 星期、中段时间、右段待办数 + 电量百分比 + 电量图标 + WiFi 图标。**所有面板共用同一条页首**。**日期与星期只在页首出现一次**，面板内部不再重复画；**中段时间在面板一隐藏**（面板一左栏已有一个 62 px 的大钟，页首再放小钟就是同一屏两个时间）。右段四个元素从右边缘往左排，每项宽度都实测（`tw()`），不写死坐标。
_Avoid_: 状态栏、顶栏、header

**无标签数值**：
只有数字和单位、没有中文标签的数值展示（面板一的温度 `24.5°C` 与湿度 `48%`）。左侧本来只放「此刻 + 环境」，加了「温度」「湿度」两个标签反而挤；上板实测 `logisoso32_tf` 写 `24.5°C` 要 103 px、`48%` 要 60 px，192 px 内宽绰绰有余。但 `-12.3°C` 要 125 px，会压到那只鹅身上，所以温度串超 104 px 时自动降一档字号。
_Avoid_: 数值标签、中文单位前缀

**宠物（鹅）**：
面板一左下角 84×107 px 里的**一只白鹅**，是工作台状态的具象外壳（不高兴 = 待办逾期 / 服务器挂 / 电量低），**没有自己的待办**；长期状态只有「羁绊天数」。**v0.1.3 起**替换虚线占位框，**区域与左栏其余元素坐标一字不改**。形象是 40×56 的**逐帧点阵**（`src/goose_frames.h`，`.pio/goose_frames.py` 手工编辑、`.pio/make_frames_h.py` 生成），用 `drawXBMP` 贴出；1bpp 没有灰阶，所以鹅靠实心剪影 + 白色负形（眼、翅、喙缝）成立，尾巴留尖、脖子占竖直约 1/3。见 ADR-0019。
_Avoid_：电子宠物、桌面宠物、吉祥物（前两者隐含喂养与死亡，本项目明确不做）、宠物插件（v0.1.3 起它有具体形态，不叫插件）

**宠物插件占位**：
v0.1.2 及以前，上面那块 84×107 位置画的是**虚线框 + 居中两行「宠物」「插件」**，虚线本身就是「这不是最终图形」的标记。**该形态已被「宠物（鹅）」取代**（v0.1.3，ADR-0019）；术语留档是为了读旧固件、旧截图与旧 ADR 时不困惑。
_Avoid_：拿「占位」称呼 v0.1.3 之后的鹅

**实测字宽**：
直接从 u8g2 字库二进制里量出来的字符宽度（用 `u8g2_GetStrWidth()` 的同一套规则，但离线完成）。**注意它只可信到「排候选顺序」这一步**：上板比对发现，离线解析器在 **ASCII 上系统性偏小约 2~7%**（`logisoso62_tn` 的 `10:22` 离线 179 / 上板 **192**），而 **CJK 完全一致**（wqy12 的星期表头两边都是 81 px）。所以**版面数字一律以设备 `getUTF8Width()` 的读数为准**，开机 `[font-test]` / `[font-cand]` 两组日志会把基准钉住。

_Avoid_：估算值、标称宽度
_Avoid_: 估算宽度、字符宽度（说的是概念不是本项目的做法）

**页尾**：
常驻在屏底的一行，左侧是当前面板名，右侧是状态提示（分页时是页码，断网时是「离线」）。**所有面板共用同一条页尾**。
_Avoid_: 底栏、footer

**全反射屏（RLCD）**：
靠环境光成像、**没有背光**的反射式液晶屏。本板 4.2 寸、1bpp 黑白、驱动 IC 为 **ST7305**。因为无背光，**暗处看不见**，摆放与休眠策略都必须考虑这一点。
_Avoid_: 电子墨水屏、E-Ink（成像原理完全不同）、LCD（会与带背光的 LCD 混淆）

**高功耗模式（HPM） / 低功耗模式（LPM）**：
ST7305 面板的两种自刷新档位，由命令 `0x38` / `0x39` 切换。HPM 下面板高频自刷新，改动立刻可见；LPM 降到低频，**写入后要等约 1 秒才显示**。本项目空闲时切 LPM 省电，有交互时切回 HPM。**切 LPM 不熄屏**（不发送熄屏命令）。两档的实际帧率由初始化里的 `0xB2` 决定。
_Avoid_: 省电模式、休眠模式、深睡（深睡是 CPU 侧的完全断电，与面板自刷新档位不是一回事）

**对比度档位**：
ST7305 的 10 位对比度寄存器（命令 `0x81`）所决定的黑白反差强弱。本项目分 5 档（`{40, 50, 60, 70, 80}`，默认第 3 档 60），**跨重启保留**（NVS，见「设置版面」）。面板上 BOOT 长按是热键，关于页设置版面里 BOOT 长按切选中行的选项 —— 两条路径改同一个值、写同一份 NVS。
_Avoid_: 亮度、brightness（全反射屏没有背光，不存在亮度）、连续可调（本项目是离散档位）

**KEY 键 / BOOT 键 / PWR 键**：
板载三颗可按器件中的两颗是本项目的输入：**KEY**（GPIO18）是主要操作键，**BOOT**（GPIO0）是次要操作键。**PWR** 是纯电源开关（无任何 GPIO 标注、不可读电平），**不作为输入**。
_Avoid_: 按钮 A / 按钮 B（本项目不用 A/B 编号）、电源键当按键用

**电池分压点**：
电池电压经板载 200 kΩ / 100 kΩ 分压后接到 GPIO4 的那一点，电压是电池电压的 **1/3**。电量百分比由这个点反算，分压比是**硬件事实**，不是可调参数。
_Avoid_: 电池脚、ADC 脚（说的是位置不是信号）

**电量百分比（SoC）**：
页首那个 `96%`。由「电池分压点」的电压经一条**四点三段折线**（4.12 / 3.90 / 3.60 / 3.00 V ↔ 100 / 70 / 25 / 0 %）反推而来，**不是电量计的读数**——本板没有电量计 IC。锚点是**工程近似，不是这颗电池的实测放电曲线**，见 ADR-0018。它承诺的是「随放电分段单调下降、两端不撒谎」，**不承诺 ±N% 的准确度**；充电时端电压虚高、满载时端电压虚低，两个方向都会让数字偏，本版**不做补偿**（软件既判断不了是否在充电，也测不到放电电流）。
_Avoid_: 电量、剩余电量（那更接近能量）、电池健康度（那是 SOH，另一件事）、电压百分比

> 📌 **实测（2026-10-24 20:23 → 10-25 11:23，面板一满载连续 15 小时零复位）**：4.095 V → 3.918 V（−177 mV），96% → 72%，约 **1.6 个百分点/小时**。两端都不是开路电压——起点插着 USB（偏高）、终点满载（偏低）——所以真实掉幅比 24 个点更大；「72 ÷ 1.6 ≈ 45 小时」是剩余时间的**上限**，不是估计值。同一时段 `heap` 最低水位只比当前低 208 B。

**显示死区**：
新读数与**当前显示值**之差达到阈值才更新屏幕的规则（v0.1.2 起）。比较对象是「屏上现在那个数」，**不是「上一次读数」**——后者会让缓慢漂移一路累积，最后在某一帧连跳好几格。阈值按**百分比**定：显示值 > 10% 用 2%，≤ 10% 用 1%（低电量时「还能撑多久」比「数字稳不稳」重要）。串口日志永远打**原始估算值**，被挡下时才追加 `(disp N%)`。
_Avoid_: 迟滞 / hysteresis（电路词）、滤波、平滑（死区不改变估算值，只决定要不要换屏上那个数）

> 📌 **v0.1.2 上板实测（2026-10-24）**：`pack=4.095 V` → 屏上 `96%`，与手算 `70 + (4.095 − 3.90) / 0.22 × 30 = 96.6 → 截断 96` 一致；页首右段 `待办4 + 96% + 电池图标 + WiFi` 目视确认，`%` 字形正常、不与待办挤在一起。**未观测的两条**：`--%` 未知态（健康板上首次读数在首次绘制之前完成，触发不到）、`(disp N%)` 死区行（插着 USB 电压稳定在 4.095 V，没等到跳变）。

**充电指示灯不可读**：
本板的 CHG（充电）与 WRN（反接）指示灯由充电管理芯片直接驱动，**没有 GPIO 可读**，因此软件**无法判断正在充电**，只能显示电量百分比。
_Avoid_: 充电状态图标、充电中标志

## 数据层

**指标快照（snapshot.json）**：
服务器上由 cron 脚本采集的一组本机运行指标（CPU / 内存 / 负载 / 磁盘 / 网卡 / 服务探活 / 证书天数），每分钟原子写一次。**设备端只读不改**，沿用 `status-oled3` 已上线的契约（19 字段，本项目议定扩到 **22**：新增 `svc_select` / `svc_wb` / `svc_ma12`），见 [`../status-oled3/docs/adr/0012-json-field-contract-for-server-side-documents.md`](../status-oled3/docs/adr/0012-json-field-contract-for-server-side-documents.md)。
_Avoid_: 服务器状态、状态接口、健康接口

**本机 vhost 探针 / 出站 TCP 探针**：服务探活的两种型式。**本机 vhost 探针**是服务器去请求自己的 `https://127.0.0.1/` 并用 `Host` 头钉住真实域名，判据是 HTTP 200——测的是「本机这套栈在不在服务」，不探公网、不校验证书；**出站 TCP 探针**是从服务器向外部地址建一次 TCP 连接（`<tcp-host>:<port>`），只要连上就算正常，测的是「本机出得去、对端在监听」。**两者的失败含义相反**：前者 ✗ 是本机栈没服务，后者 ✗ 是本机出不去 / 对端挂了 / 链路断了。

_Avoid_: 网站健康、在线状态、ping 一下

**行程日**：当月里存在行程的那一天。月历格内底部用计数点表示这天有几条行程，**只标本月**，首尾补白的上 / 下月日期不标（那些格子本来就不画外框，见「非本月日期」）。

_Avoid_: 日程表、忙碌日

**非本月日期**：月历窗口里属于上个月或下个月的日期（例如行 2 末尾的 `11/01`）。这类格子**只画数字、不画外框**——框表达「这一格属于本月网格」，没有框就是「这天不在这儿」。

_Avoid_: 灰显日期、置灰、变淡

_Avoid_: 日程表、忙碌日

**行程标注**：月历格内底部的 1–3 个 3×3 px 实心方块，每个点代表一条行程；超过 3 条饱和成 3 个点。当天（填黑格）上的点画成白色。数据来自待办摘要的 `trips.days`：**扁平天号数组、重复即多点**（`[22,24,27,27,27]` = 27 号三个点），当月没有行程时整个字段省略。

_Avoid_: 小圆点、日历角标、事件标记

**月历滚动窗口**：右栏月历固定只画三行——行 0 上周、行 1 本周、行 2 下周，**今天恒落在中间行**。不是整月视图：行 2 里可能混着下个月的日期（如 11/01），靠「非本月日期不画外框」与行程标注「只标本月」双重避免误读。选它是因为整月最少要 4 行、放不进三行，而用户要求把省下的位置留给待办。

_Avoid_: 整月视图、日历页、按周翻页

**待办摘要（/api/todo-device）**：
网站后端从 `studio.db` 现算的**派生只读投影**（不是实体表，不能按 id 单取），`schemaVersion = 1`。一次响应 = `generatedAt` + `stats{pending, overdue, todayDue, earlier}` + `items[0..6]`（`id`/`title`/`priority`/`category`/`dueDate`/`tags`/`updatedAt`）+ `truncated` / `remaining`。窗口 `[本周一 − 14 天, 本周日]`、逾期置顶、上限 6 条都由服务端算好；**标题原文不截断**，设备自己按像素裁；`dueDate` 是**纯日期**，`tags` 恒为 `[]`。见 ADR-0020。
_Avoid_: 待办数组（没说清是哪一层的数组，服务端在 `items` 里给的就是数组，但设备消化它的过程不是「读一个数组」）、任务列表接口、todo list API、todo.json（那是已退役的旧形态）

**宽进（tolerant parse）**：
读待办摘要时对**下一版契约才有的字段**一律不判失败：`today` 缺失退回本机日期、`stats.undated` / `stats.outOfWindow` 缺失就不做恒等式自检、`trips` 缺失就不画点。理由是这些字段上线有时间差——严格校验会让屏停在「等待数据」，而它本来能显示上一份好数据。
_Avoid_: 兼容模式、宽松解析（都不说清「宽松的是哪一层」）

**未完成数**：
待办摘要里 `stats.pending` 的值——**全部未完成条数**（含无截止日期的、含窗口外的），在任何筛选 / 截断之前算。它是页首右段那个数字，也是页尾 `+N` 的被减数：屏上一行一条，`N = pending − 屏上行数`。为 0 时**照常显示 0**（不隐藏、不换成别的字样），避免页首元素宽度跳动。
_Avoid_: 待办数（未定义是总数还是未完成数）、剩余待办、`total − done`（旧契约的口径，已经不存在）

**到期（due）**：
待办条目的截止**日期**，格式是纯日期 `YYYY-MM-DD`（不是时间戳，也没有时分）。屏上不显示绝对日期，只显示换算出来的相对描述，六档：`逾期N天` / `今天` / `明天` / `N天后`（≤7 天）/ `MM-DD`（更远）。「今天」的权威来源是响应里的 `today` 字段，不是本机 RTC——RTC 漂一格，整列会错一格。
_Avoid_: 截止时间、deadline、`2026-10-25 18:00`（旧的绝对时间戳形态）

**停更**：
设备已连续若干个轮询周期没有拿到新的有效数据。**停更是可观测的结果，不是原因**——服务器宕机、设备断网、TLS 握手失败、DNS 解析失败都会表现为停更。屏上区分「连不上」与「连上了但数据旧」两种情况。
_Avoid_: 超时、掉线、失联

**龄期**：
设备成功收到最后一份有效数据到现在经过的时间，用**设备自身的单调时钟**算，不用服务器时间戳相减。停更时逐项标出龄期，让「这是 3 分钟前的数」与「这是刚拿到的数」在屏上可区分。
_Avoid_: 最后更新时间戳、age（指服务器侧的时间戳字段）

**共享监控密钥**：
设备访问 `/status/` 下文档时带的头 `X-Monitor-Key`，由 nginx 用 `map` 校验。**v0.1.4 起它只服务指标快照**——待办改用独立的设备密钥（见下一条与 ADR-0021）。
_Avoid_: API Key、Token、鉴权密码

**设备密钥**：
设备访问 `/api/todo-device` 时带的头 `X-Todo-Device-Key`，由 Go 后端用常量时间比较校验，值与服务器 `/etc/siungo/upload-server.env` 里的 `TODO_DEVICE_KEY` 同源（43 字符）。**未配置时服务端恒回 401**，且 401 对「key 错 / 没带 / 服务端没配」三态同形——屏上的「密钥未配置」只能是提示，不是诊断结论。见 ADR-0021。
_Avoid_: 监控密钥（那是另一把）、token

**轮询周期**：
设备向服务器发起一次 GET 的间隔。指标快照 **15 秒**（连续失败线性退避 15s → 30s → 60s → 120s 封顶）；待办摘要 **5 分钟**（失败退避 30s → 60s → 120s → 240s → 300s 封顶，成功后立刻回到 5 分钟）。**认证 / 部署类错误（401 / 404）走慢探**：30 分钟一次，因为这两种错误会随服务端修复自愈，而永久停轮询需要人去按板子。
_Avoid_: 刷新率、采样率

**羁绊天数**：
宠物（鹅）**唯一的长期状态**：设备与用户「一起过了多少天」。取 **RTC 的本地日历日**（复用 `tz` 的时区与 DST 表），跨天检测挂在已有的 60 s 节拍里比对 `yyyy-mm-dd`，**不在开机路径上判**——放在开机路径上，常年不关机的设备就永远不涨。**只增不减**：断电五天后回来一次涨 5 不涨 1，它记的是日历不是开机次数。NVS namespace `rlcd`，键 `bondDay` + `bondDays`，**一天最多写一次**。因为屏上没有任何文字，这个数**不直接显示**，只用里程碑配件（第 30 天帽子；第 7 天围巾 2026-10-25 取消）表达成长。见 ADR-0019。
_Avoid_：亲密度、等级、经验（都不是日历量，也都可能被玩坏）、在线天数（那不是这台设备的语义）

## 设备状态层

**电源档位**：
由电池电压推出的两档工作策略：**USB 全速**（电压 > 4.05 V，服务器轮询与重绘都按正常节奏）与**电池省电**（电压 < 3.9 V，轮询与重绘节奏放宽、优先切 LPM）。两档之间是过渡区，按就近原则取一档。
_Avoid_: 充电模式、供电模式（会与 USB/电池来源混淆）

**WiFi 三态**：
WiFi 链路的三种可视状态：**已连**（完整图标）、**连接中**（半空图标）、**断开**（叉号图标）。断网时**不隐藏图标**，而是换成叉号——图标消失与叉号在屏上是两种不同的信息。
_Avoid_: 信号强度、WiFi 等级（那是有连上时的强弱，不是连通性）

**事件驱动重绘**：
只有「有东西变了」才重画对应区域，不是定时全屏刷新。变化源包括按键、时间跳秒、传感器新值、服务器新数据、WiFi 状态翻转。
_Avoid_: 轮询刷新、定时刷新

**局部重绘**：
只把屏幕上一小块区域重新推给面板，而不是整屏重写。本板行方向的可写粒度是 **8 px**（与 u8g2 的 tile 高一致），列方向按 12 px 块切分、最多向外多刷 8 列。
_Avoid_: 增量刷新、diff

**脏标记**：
标在某个面板上、表示「这个面板需要重画」的一位状态。面板切换时先检查脏标记，没有脏就不画。
_Avoid_: dirty bit（那是指单个位，语义更窄）

**动画窗口**：
宠物动画**只在有头有尾的一段时间里跑 8 Hz**（事件后 3–5 秒），其余时间是 1 Hz 的 idle 微动；低于 3.9 V 时窗口缩短为事件触发。窗口期间面板 `0xB2` 由 `0x02`（1 Hz）切到 `0x05`（8 Hz）并强制 HPM（`0x38`），窗口结束切回并沿用既有 30 秒空闲规则回 LPM。idle 的 1 Hz 是**蹭主循环本来就有的每秒整帧刷**，不额外增加刷新次数；8 Hz 那几秒则是全帧重画，约 10% 的刷新占空。**8 Hz 低于 §7 第 5 项给局部重绘定的 ≥10 fps 重开线**，所以窗口走整帧刷、不修 R1 的 tile 映射。见 ADR-0019。
_Avoid_: 高帧率模式、流畅模式、动画开关（它不是用户可以开关的「模式」，是一个由事件开启的窗口）

**关于页**：
双击 KEY 进入的一页，显示设备信息与固件版本，**兼作使用说明**（面板切换与按键含义写在这一页上）。它不是第四个面板，而是一张覆盖层。上半区（设备信息）固定；**下半区互斥两版**：教程版面（默认，6 行手势表）与设置版面。
_Avoid_: 帮助页（它是设备信息 + 使用说明的复合页，不是单纯的帮助）、独立设置页（设置不是一张独立的页，见「设置版面」）

**设置版面**：
关于页**下半区的一个版本**，不是一张独立的页、也不是浮在关于页上的覆盖层。上半设备信息仍然在场，被替换的只有下半区原本的手势教程表。版面内 BOOT 短按 = 选中行切下一行（单选循环）、BOOT 长按 = 切换选中行的选项、KEY 双击 = 回教程版面。**v0.1.5 后续起共五项**：对比度、声音（总闸）、音量、整点报时、夜间静音 —— 超过版面上限的 4 行（`ui.cpp` 的 `y > 240` 截断），所以从本版起用**固定窗口滚动**（窗口永远 4 行，选中行滚出可见区时才整窗上滚一行），窗口覆盖范围画在「设置」标题行右侧（`1-4/5`、`2-5/5`，ADR-0023）。两行键位说明与底部两行固定提示**不参与滚动**。各设置项见各自词条。设置值写在 NVS（namespace `rlcd`，变更即写），因此设置版面开着时**不进 LPM**（LPM 下写入有约 1 秒延迟，那 1 秒里按键像失灵）。
_Avoid_: 设置页、设置界面、配置页（都不是独立的一页）、菜单页（本项目没有菜单层级）

> 📌 **v0.1.1 已上板验收（2026-10-24，ADR-0017）**：对比度跨重启保留（拔电重启后仍第 5 档、串口 `src=nvs`）、NVS 越界回默认档并打 `out of range`、设置版面静止 60 秒不进 LPM。

**语音链路（仍延期）**：
录制音频（麦克风 → ES7210）、把音频送往服务器 AI、以及播放服务器下发的语音。**到 v0.1.5 为止仍不实现**，只在策划案里写清技术路线与前置条件（ADR-0011）。
⚠️ **v0.1.5 起的边界修正**：设备**能本地播放提示音**了（见「提示音」），但那**不属于语音链路** —— 它不碰麦克风、不碰编码、不碰网络，PCM 直接编进固件。ADR-0011 里「服务器侧 ASR/TTS 从未存在、nginx 无 Upgrade 头、2 核 1682 MB 跑不了 FunASR、海外 443 被封、小智固件不能共存」这些事实**一条都没被这次推翻**。
_Avoid_: 语音功能、录音功能（本期仍然不存在）、音频功能（把「提示音」和「语音」混成一件事，正是这次要拆开的）

**提示音（chime）**：
**本地生成、不经过网络的短音**，用 ES8311 codec + NS4150B 功放（GPIO46）+ 外接 8 Ω 2 W 喇叭播放，PCM 数据编进固件。v0.1.5 只有一种用途：整点报时（见「整点报时」）。每次播放走一遍 `esp_codec_dev_open` → `write` → `close`，**功放由驱动随 open/close 成对上电/断电，代码不自己碰 GPIO46**（`esp_codec_dev.c:143` 的 `disable_when_closed = true`）；代价是每次出声都要付一遍 I2C 配置 + I2S 启停的固定开销，且功放工作时**会抬板温**。响度由「音量」的五档决定，波形幅度（`kChimeAmplitude`）只负责留余量防削顶，**不是音量旋钮**（ADR-0023）。

⚠️ **长度不是随便定的**：两声「嘀嘀」合计 **340 ms**（150 ms 响 + 40 ms 静 + 150 ms 响），关流前还要再等 60 ms 让 DMA 排空。原先是 150 ms，实测**只有第一声响、后面全哑** —— 短音频被开流关流的固定开销整段吞没，而 `write()` 照样返回成功。**加长不是为了让声音更好听，是为了让它出得来。**
_Avoid_: 提示音效、声音文件、音频播放（都不说清是本地合成还是播放音频文件）、蜂鸣器（本板没有蜂鸣器，这条链路完全不同）

**音量**：
提示音的**响度五档**，设置版面的第 3 项，调的是 ES8311 的 DAC 增益（`esp_codec_dev_set_out_vol`），量纲 0..100。档位表 `{40, 60, 75, 85, 95}`，**默认第 4 档 85**（`kVolumeDefaultIdx = 3`）—— 这个值不是挑出来的，是 v0.1.5 排查无声时唯一被实测证明"听得见"的那个值，默认落在它上面意味着老设备升级后听感不变。值在**每次开流之后**重新读一遍并写进 DAC，所以改档位下一次出声自动生效；这不是可省的优化，`es8311_suspend()` 会把 DAC 音量寄存器清成静音值，而 `esp_codec_dev_open()` 每次都先 suspend 再 start。

⚠️ **已知缺陷（ADR-0023 遗留问题）**：五档在实际听感上**区分度不足**，用户切档时反馈"音量都是相同的"。原因是 `esp_codec_dev_set_out_vol()` 的量纲 0..100 **不是 dB**，它到 ES8311 `DAC_REG32` 的映射由 `es8311_set_vol()` 的查表决定，高位段被压缩 —— `40 → 95` 跨了 55 格，实际增益只有个位数 dB。要修得先量出每档真实响度再重选值，或改用 PCM 幅度做指数衰减绕开那张表。
_Avoid_: 音量开关（它是五档，不是开关）、响度（口语可，本项目用「音量」）、PCM 幅度（那是「提示音」里 `kChimeAmplitude` 的职责，不是这一项）

**整点报时**：
每到整点（分钟数从 59 进到 00，且小时数在 08–21 之间时听得见）响一声提示音：**340 ms 两声「嘀嘀」**。**它只管「是不是整点」，不管时段** —— 时段判断全部由「夜间静音」一处负责，这条里不写任何时窗常量。检测挂在 `workclock`（软件时钟）的小时数变化上，**不直读 RTC** —— 否则会出现「屏上显示 14:59、喇叭却报 15:00」的自相矛盾。主循环被阻塞跨过两个整点只响一次。
_Avoid_: 报时功能、闹钟（闹钟是用户设定的某个时刻，整点报时是每小时固定触发）、报时按钮（屏上是设置行，不是按键）

**夜间静音**：
**全系统唯一的时段判断点**：开（默认）时 21:00–08:00 一律不出声，关时允许 24 小时出声。窗常量在 `config.h`（`kQuietStartHour = 21` / `kQuietEndHour = 8`），**不在设置里可调** —— 调时段要加两项，而设置版面已经在滚动了，多两项只会让「滚到底才看得见」这件事更糟。
_Avoid_: 夜间报时（方向相反：那是「夜里也要报」，这是「夜里不许响」）、免打扰（手机语境，本项目没有来电）、静音模式（听起来像把屏也关了，而屏幕不熄）

## 里程碑

**可测断言**：
每个里程碑结束时必须能当场验证的一句话结论，形式是「在某条件下能看到某结果」。里程碑不是「代码写完了」，是「断言成立」。
_Avoid_: 验收标准（本项目用「断言」这个词，因为验收项就是可当场跑的那一下）

**M0 / M1 / M2 / M3 / M4 / M5 / M6 / M7 / M8 / M9**：
本项目的十个里程碑，依次是：屏幕点亮 → 页面骨架与两键手势 → 传感器 / 电量 / WiFi / 服务器面板真数据 → 待办契约与服务器脚本 → AI 占位接口与文档收尾 → 关于页设置版面与对比度持久化（v0.1.1）→ **电量百分比：分段折线 + 页首数字 + 显示死区（v0.1.2）** → **宠物插件：面板一左下角的一只鹅（v0.1.3）** → **待办改接网站派生只读投影 `/api/todo-device`（v0.1.4）** → **本地提示音与整点报时：声音 / 音量 / 整点报时 / 夜间静音四项设置，设置版面改固定窗口滚动（v0.1.5）**。定义见 `策划案.md` §6。
_Avoid_: 阶段、迭代
