# pet-oled3 · 养成类掌上宠物

用 ESP32-S3 做的**单角色养成掌机**：三块 SSD1306 分饰角色 / 数值 / 日志，4x4 键盘出三个主动作，旋转编码器调参，蜂鸣器出音效，板载 WS2812 做状态灯。

> **状态：策划阶段，尚未动工。** 本目录目前只有文档，没有代码。
> 动手的第一步是 M0 bringup（见 [`docs/策划案.md` §6](docs/策划案.md)）。

| 项目 | 参数 |
|---|---|
| 目标板 | ESP32-S3-DevKitC-1 **N16R8** |
| 供电 | **全 3.3 V**，无 5 V 器件、无电平转换 |
| 第三方依赖 | 暂无（计划复用 `uptime-oled` 的 SSD1306 裸驱） |

---

## 1. 这个设备是什么

一块**掌上养成游戏机**。角色状态随**开机运行时间**演变（关机暂停，不联网、无 RTC），玩家用三个按键动作维护它。

核心循环：

```
数值随时间下降 → 角色表情变差 → 玩家察觉 → 按动作键
                                              ↓
                                     数值回升、亲密度变化
```

**三条数值互相牵制**，构成决策张力：

| 主动作 | 按键 | 主效果 | 副作用 |
|---|---|---|---|
| **喂食** | 键 1 | 饱食度 ↑ | 过饱掉心情 |
| **玩耍** | 键 2 | 心情 ↑ | 消耗体力 |
| **休息** | 键 3 | 体力 ↑ | 心情缓降 |

完整玩法见 [`docs/策划案.md` §4](docs/策划案.md)。

## 2. 硬件需求

| 器件 | 数量 | 说明 |
|---|---|---|
| ESP32-S3-DevKitC-1 (N16R8) | 1 | 板载 WS2812 RGB 在 **GPIO 48** |
| SSD1306 OLED 128×64 | **3** | 全部保持出厂地址 **0x3C**，不需要改地址电阻 |
| **PCA9548A** I2C 多路复用器 | 1 | 8 通道成品模块，**板载 10k 上拉** |
| 4x4 矩阵键盘 | 1 | 8 根线（4 行 + 4 列） |
| 旋转编码器 | 1 | 增量式，A/B 相 + 按键 |
| 无源压电蜂鸣器 | 1 | **必须是无源**，有源型发不出音阶 |

### 2.1 为什么需要 PCA9548A

三块 SSD1306 **出厂地址都是 0x3C**，I2C 是总线拓扑，靠地址区分器件——所以三块屏**不能直接并联**。

关键澄清：**换 GPIO 解决不了**。I2C 有总线概念，换引脚只改变"总线接在哪两个脚"，不改变"总线上有两个同地址器件"。

PCA9548A 把一根总线上游分成 8 路下游通道，三块屏各挂一路，**每条通道上只有一个 0x3C 器件**，冲突在通道层面被隔离。三块屏保持出厂状态，**不用动烙铁**。

> 被否决的替代方案（强制劈地址、多组 I2C 总线）与完整对比见 [ADR-0001](docs/adr/0001-use-pca9548a-for-three-displays.md)。

### 2.2 接线

**上游（ESP32 ↔ PCA9548A）**

| PCA9548A | ESP32-S3 | 说明 |
|---|---|---|
| SDA | **GPIO 8** | 建议值，待 bringup 实测确认 |
| SCL | **GPIO 9** | 同上 |
| VCC | 3V3 | 模块支持 2.3–5.5 V |
| GND | GND | |
| A0/A1/A2 | GND（跳线） | 目标地址 **0x70**，**以实际扫描结果为准** |
| RESET | 3V3 或悬空 | active-low；bringup 阶段先悬空 |

**下游（PCA9548A ↔ 三块屏）**

| 通道 | 器件 | 术语 |
|---|---|---|
| **0** | SSD1306 | **角色屏**（大图 + 表情） |
| **1** | SSD1306 | **数值屏**（三条数值条 + 数字） |
| **2** | SSD1306 | **日志屏**（事件滚动、菜单、提示） |
| 3–7 | 预留 | 0x70 已占住，未来加器件不撞地址 |

完整 GPIO 分配总表见 [`docs/策划案.md` §3.5](docs/策划案.md)。

### 2.3 ⚠️ 三条硬约束（本机实测得出，违反即不工作）

| # | 约束 | 依据 |
|---|---|---|
| 1 | I2C **禁止**接 **GPIO 1 / GPIO 2** | [`HARDWARE.md:240-250`](../HARDWARE.md) 实测：全段 `endTransmission` 返回 **5（超时）**，换 GPIO4/5 立刻通 |
| 2 | **禁止**占用 **GPIO 19 / 20** | 原生 USB D+/D-，占用即失去板载串口下载 |
| 3 | **禁止**往 SDA/SCL 重复加 4.7k 上拉 | 上游模块自带 10k、下游每块屏自带，并联会让等效阻值过低 |

> 这三条不是"注意事项"，是**实测的硬边界**。第 1 条尤其反直觉——GPIO1/2 看着是好脚位（现有项目就用 GPIO4/5），但在 S3 上接 I2C 会全段超时。

## 4. 里程碑

| 阶段 | 内容 | 状态 |
|---|---|---|
| **M0** | **硬件 bringup** —— 证明 PCA9548A + 三块屏这条链路真的通 | ⬜ 未开始（**阻塞项**） |
| M1 | 输入输出基元：键盘扫描、编码器、蜂鸣器 PWM、WS2812 | ⬜ |
| M2 | 显示层：`Display` 跨通道封装、三屏绘制、刷新调度器 | ⬜ |
| M3 | 游戏内核：三条数值 tick、主动作联动、成长阶段状态机 | ⬜ |
| M4 | 打磨：数值平衡、音效、灯效、长跑测试 | ⬜ |

**M0 的验收标准**：三块屏能显示**三个不同的字符串**，且任意时刻单独刷新其中一块不干扰另外两块。

> ⚠️ 必须显示**不同内容**——同内容无法区分是否真的切换成功了。

各里程碑的详细任务清单见 [`docs/策划案.md` §6](docs/策划案.md)。

## 5. 动手前先验这两件事

验证成本极低，但猜错代价很大（详见 [`docs/策划案.md` §7](docs/策划案.md) 待验证清单）：

1. **PCA9548A 实际地址** —— 成品模块跳线可能焊死，不一定遵守「全接地 = 0x70」。**扫描后以实际结果为准，不要硬编码。**
2. **4x4 键盘是矩阵还是编码型** —— 数排针：**8 根 = 矩阵**（本文档的假设），**4 根 = TM1650 之类的 I2C 编码键盘**。若是后者，它会占用一个 I2C 地址、需要挂到 PCA9548A 的空闲通道，**整个拓扑要改**。

另外顺带确认**蜂鸣器是否无源**：接 3.3 V 直接通电，响 = 有源（需换件），不响 = 无源。
