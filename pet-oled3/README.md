# pet-oled3 · 养成类掌上宠物

用 ESP32-S3 做的**单角色养成掌机**：三块 SSD1306 分饰角色 / 数值 / 日志，两个轻触按钮驱动全部交互，有源蜂鸣器出声，板载 WS2812 做状态灯。

> **状态：M0 bringup 已完成（2026-10-21），项目进入 M1。** 本目录现在**有代码**了：`src/` 是 M0 固件（`main.cpp` + 从 `status-oled3` 复用改造的驱动），`platformio.ini` 是构建配置。
>
> 📌 **M0 实测结论**：PCA9548A **0x70 应答**；**ch0/ch1/ch2 三通道 `endTransmission()` 全程返回 0（ACK），无一次 5**；三块屏各显示各的内容；**4 种按钮手势全部触发**；**蜂鸣器驱动档读回 = 3**。1 Hz 节拍连续 6 分钟零漂移。
>
> 📌 **硬件接口与 `status-oled3` 完全同一套**（2026-10-21 用户决策）：上游 SDA=GPIO5 / SCL=GPIO4、PCA9548A RST=GPIO8、按钮=GPIO6/7、有源蜂鸣器=GPIO21、WS2812=GPIO48。驱动层直接复用 `status-oled3`。见 [ADR-0006](docs/adr/0006-hardware-interface-aligned-with-status-oled3.md) / [ADR-0007](docs/adr/0007-two-buttons-only-input.md)。

| 项目 | 参数 |
|---|---|
| 目标板 | ESP32-S3-DevKitC-1 **N16R8** |
| 供电 | **全 3.3 V**，无 5 V 器件、无电平转换 |
| 第三方依赖 | 暂无（驱动层复用 `status-oled3`，WS2812 库来自 `blink3`） |

## 1. 这个设备是什么

一块**掌上养成游戏机**。角色状态随**开机运行时间**演变（关机暂停，不联网、无 RTC），玩家用**两个按钮**维护它。

核心循环：

```
数值随时间下降 → 角色表情变差 → 玩家察觉 → 选动作 → 确认
                                                      ↓
                                     数值回升、亲密度变化
```

**三条数值互相牵制**，构成决策张力：

| 主动作 | 怎么触发 | 主效果 | 副作用 |
|---|---|---|---|
| **喂食** | 光标移到「喂食」→ 按 B 确认 | 饱食度 ↑ | 过饱掉心情 |
| **玩耍** | 光标移到「玩耍」→ 按 B 确认 | 心情 ↑ | 消耗体力 |
| **休息** | 光标移到「休息」→ 按 B 确认 | 体力 ↑ | 心情缓降 |

> 三个主动作**没有各自的物理按键**——两键方案里它们是主界面光标的三个选项（[ADR-0007](docs/adr/0007-two-buttons-only-input.md)）。

完整玩法见 [`docs/策划案.md` §4](docs/策划案.md)。

## 2. 硬件需求

| 器件 | 数量 | 说明 |
|---|---|---|
| ESP32-S3-DevKitC-1 (N16R8) | 1 | 板载 WS2812 RGB 在 **GPIO 48** |
| SSD1306 OLED 128×64 | **3** | 全部保持出厂地址 **0x3C**，不需要改地址电阻 |
| **PCA9548A** I2C 多路复用器 | 1 | 8 通道成品模块，**板载 10k 上拉** |
| 轻触按钮 | **2** | 内部上拉，按下接地为低电平（GPIO 6 / 7） |
| 有源蜂鸣器 | 1 | **有源型**（通 3.3V 即响，音高不可改，只做通断节奏） |
| ~~4x4 矩阵键盘~~ | — | ❌ **已取消**（[ADR-0007](docs/adr/0007-two-buttons-only-input.md)） |
| ~~旋转编码器~~ | — | ❌ **已取消**（同上） |

### 2.1 为什么需要 PCA9548A

三块 SSD1306 **出厂地址都是 0x3C**，I2C 是总线拓扑，靠地址区分器件——所以三块屏**不能直接并联**。

关键澄清：**换 GPIO 解决不了**。I2C 有总线概念，换引脚只改变"总线接在哪两个脚"，不改变"总线上有两个同地址器件"。

PCA9548A 把一根总线上游分成 8 路下游通道，三块屏各挂一路，**每条通道上只有一个 0x3C 器件**，冲突在通道层面被隔离。三块屏保持出厂状态，**不用动烙铁**。

> 被否决的替代方案（强制劈地址、多组 I2C 总线）与完整对比见 [ADR-0001](docs/adr/0001-use-pca9548a-for-three-displays.md)。

### 2.2 接线

**上游（ESP32 ↔ PCA9548A）**

| PCA9548A | ESP32-S3 | 说明 |
|---|---|---|
| SDA | **GPIO 5** | `status-oled3` bench 实测值（2026-10-17） |
| SCL | **GPIO 4** | 同上 |
| VCC | 3V3 | 模块支持 1.65–5.5 V |
| GND | GND | |
| A0/A1/A2 | GND（跳线） | 目标地址 **0x70**，`status-oled3` 实测命中 |
| RESET | **GPIO 8** | active-low，保留硬复位能力 |

> ⚠️ **SDA/SCL 线序不可交换**：实物是 GPIO5→SDA、GPIO4→SCL，两线交叉过。换过来后电气指标全正常但**没有任何器件应答**。`status-oled3` 为此查了 36 小时。完整教训见 [`HARDWARE.md`](../HARDWARE.md) §4.5。

**下游（PCA9548A ↔ 三块屏）**

| 通道 | 器件 | 术语 |
|---|---|---|
| **0** | SSD1306 | **角色屏**（大图 + 表情） |
| **1** | SSD1306 | **数值屏**（三条数值条 + 数字） |
| **2** | SSD1306 | **日志屏**（事件滚动、菜单、提示） |
| 3–7 | 预留 | 0x70 已占住，未来加器件不撞地址 |

**其余器件**

| 器件 | ESP32-S3 | 说明 |
|---|---|---|
| 按钮 A（选动作 / 光标下移） | **GPIO 6** | `INPUT_PULLUP`，按下接地为低 |
| 按钮 B（确认 / 执行） | **GPIO 7** | `INPUT_PULLUP`，按下接地为低 |
| 有源蜂鸣器 | **GPIO 21** | 推挽输出，**HIGH 响**；只做通断节奏，不出音阶。⚠️ **固件必须把该脚驱动强度提到 `GPIO_DRIVE_CAP_3`**（默认档只有 20 mA，蜂鸣器典型 20–30 mA，属临界）——[ADR-0010](docs/adr/0010-buzzer-direct-drive-needs-strongest-drive-cap.md) |
| WS2812 RGB | **GPIO 48** | 板载，固定 |

完整 GPIO 分配总表见 [`docs/策划案.md` §3.5](docs/策划案.md)。

### 2.3 ⚠️ 硬约束（本机实测 / datasheet 核实得出，违反即不工作）

| # | 约束 | 依据 |
|---|---|---|
| 1 | I2C **禁止**接 **GPIO 1 / GPIO 2** | [`HARDWARE.md`](../HARDWARE.md) §6.1 实测：全段 `endTransmission` 返回 **5（超时）**，换 GPIO4/5 立刻通 |
| 2 | **禁止**占用 **GPIO 19 / 20** | 原生 USB D+/D-，占用即失去板载串口下载 |
| 3 | **禁止**往 SDA/SCL 重复加 4.7k 上拉 | 上游模块自带 10k、下游每块屏自带，并联会让等效阻值过低 |
| 4 | I2C **SDA/SCL 线序不可交换**（GPIO5→SDA、GPIO4→SCL） | [`HARDWARE.md`](../HARDWARE.md) §4.5：接反时电气全正常但**无器件应答**（36h 排查） |
| 5 | **禁止**占用 **GPIO 38**（除非加第三键） | 现为保留空闲脚（[ADR-0007](docs/adr/0007-two-buttons-only-input.md)） |
| 6 | **禁止**占用 **GPIO 0 / 3 / 45 / 46**（strapping 脚） | ESP32-S3 datasheet v2.2 §2.3.4 / §3。⚠️ **MTDI 是 GPIO 41 不是 GPIO 12**，GPIO 12 是普通 IO |
| 7 | **禁止**在 **GPIO 7** 上同时接 DHT11 数据脚 | 与 `dht11-oled` 二选一（[`HARDWARE.md`](../HARDWARE.md) §1.2）；DHT11 自带上拉会与按钮内部上拉并联 |

> 这些不是"注意事项"，是**实测与规格的硬边界**。第 1 条尤其反直觉——GPIO1/2 看着是好脚位（现有项目就用 GPIO4/5），但在 S3 上接 I2C 会全段超时。第 4 条同样反直觉：接反了电气指标全正常，却一个器件都不应答。

## 5. M0 已经查通的事，不要重复排查

`status-oled3` 已经把本机这条链路查通了（2026-10-17），**不要重复排查已结案的问题**：PCA9548A 地址 0x70、I2C 线序、上拉归属、模块好坏、蜂鸣器类型，全部已实测确认。`pet-oled3` 的 M0（2026-10-21）又在这批模块上复验了一遍，结论一致。

M0 当时的检查顺序（**已执行，结论已固化进代码与 ADR**）：

1. **先查线序** —— 实物是 GPIO5→模块 SDA、GPIO4→模块 SCL（**不是反的**）。这是 36 小时排查的教训来源。
2. **再扫 I2C** —— 本项目这批 PCA9548A 地址 **0x70**（与 `status-oled3` 一致）。
3. **逐通道探 0x3C** —— ch0/ch1/ch2 三个下游屏全部 ACK。
4. **两键 + 蜂鸣器** —— 4 种手势全部触发，蜂鸣器驱动档读回 = 3。

M0 的固件在 `src/main.cpp`；串口原始记录在 `.doc/m0-serial-20261021.txt` 与 `.doc/m0-button-test3.txt`（**过程产物，已 gitignore**，与 `status-oled3` 的 `.doc/` 同一约定）。

> ⚠️ 换脚位或重新初始化 I2C 时，**必须先 `Wire.end()` 再 `Wire.begin()`**——ESP32 Arduino 框架的 `Wire.cpp` 里第二次 `begin()` 是 no-op（永远不 `initPins()`），会导致"改了脚位却还是旧脚在说话"的假测量。

完整待验证清单见 [`docs/策划案.md` §7](docs/策划案.md)（**12 项已全部结案**）。
