# 6. 硬件接口与 status-oled3 统一：同一套引脚、同一个蜂鸣器类型

日期：2026-10-21

## 状态

已接受

## 背景

`pet-oled3` 初版策划案（2026-10-15）里，硬件是一套**自拟**的接口：

| 项目 | 初版规划 | 依据 |
|---|---|---|
| I2C 上游 | SDA=GPIO 8 / SCL=GPIO 9 | 规划值，"待 bringup 实测确认" |
| 输入 | 4x4 矩阵键盘（行 10–13、列 …）+ 旋转编码器（A/B 相 + 按键） | 规划值 |
| 蜂鸣器 | **无源**压电型 + LEDC `ledcWriteTone` 出音阶 | 未确认类型 |

2026-10-21 起，用户明确：**硬件接口已设置成与 `status-oled3` 一致**。也就是说，本项目的实物接线**已经是** `status-oled3` 那一套，策划案必须反过来对齐它，而不是继续用初版规划值。

`status-oled3` 那边这些数字**全部是 bench 实测值**，不是规划值：

| 项目 | status-oled3 实测值 | 出处 |
|---|---|---|
| I2C 上游 | **SDA=GPIO 5 / SCL=GPIO 4** | `status-oled3/src/config.h:34-35`；2026-10-17 i2c-probe v7 单点 ACK 0x70 |
| I2C 速率 / 超时 | 400 kHz / 50 ms | `config.h:36,41` |
| PCA9548A 地址 | **0x70**（A0/A1/A2 全接地） | 2026-10-17 实测 |
| PCA9548A RESET | **GPIO 8** | 2026-10-16 实测接线 |
| 按钮 A / B | **GPIO 6 / GPIO 7**（`INPUT_PULLUP`，按下接地为低） | `config.h:98-99`；2026-10-16 实测 |
| 蜂鸣器 | **GPIO 21**，**有源型**，HIGH 响 | `config.h:100,117`；2026-10-16 实测 |
| WS2812 | **GPIO 48**（板载） | [`../../../HARDWARE.md`](../../../HARDWARE.md) §1.1 |
| 消抖 / 长按阈值 | 20 ms / 1000 ms | `config.h:106,111` |

两处**关键事实**必须写进决策，不能只写"与 status-oled3 一致"：

1. **I2C 线序不可交换**：实物是 GPIO5→模块 SDA、GPIO4→模块 SCL，两线**交叉过**。I2C 的 START/STOP/ACK 全定义在「SDA 相对 SCL 的边沿」上，互换后从机永远识别不出 START——表现是电气指标全部正常（idle HIGH/HIGH、上拉在线、轨 3152mV、全段 `nack_addr` 且 `timeout=0`），但没有任何器件应答。`status-oled3` 为此查了 **36 小时**，一度误判「模块坏」。**以后 0x70 不应答，先查线序再查别的。**（[`../../../HARDWARE.md`](../../../HARDWARE.md) §4.5）
2. **蜂鸣器是有源型**：初版策划案规划的「无源 + LEDC 出音阶」在这颗蜂鸣器上**物理不成立**。有源蜂鸣器内部自带振荡器，音高固定不可改，软件只能靠「响多久 / 停多久」编码信息。**原 §4.4 的「升级上行旋律」「低沉拒绝音」设计作废**，音效全部退化为节奏编码。

## 考虑的方案

### 方案 A：全部对齐 status-oled3 —— 采纳

本项目的引脚表、蜂鸣器类型、驱动层接口，全部改用 `status-oled3` 的实测口径。

**采纳理由**：

1. **实物已经这样接了**。这不是"选一个方案"，是"文档追认现实"——初版规划值（GPIO 8/9、键盘、编码器、无源蜂鸣器）在实物上一条都不成立。
2. **省掉整个驱动层的工作量**。`status-oled3` 的 `pca9548a` / `screen` / `ssd1306_i2c` / `button` / `buzzer` 全部在本机跑通并有实测记录，本项目**直接复用**，新写的只有游戏内核与两键上下文状态机。
3. **消灭一整类风险**。初版规划值从未在本机验证过；`status-oled3` 的每个数字都有 bench 记录与踩坑史。**已被 36 小时排查证伪的假设（地址错、上拉缺失、模块坏、总线速度）不必再查一遍。**
4. **仓库跨项目可读**。`HARDWARE.md` §1.2 的 GPIO 表里，GPIO 6/7/21 现在是两个项目同一套接线，仓库只有一种解读。
5. **踩坑史可以继承**。线序交叉、`Wire.end()` 缺失导致换脚位无效、有源蜂鸣器不做 PWM——这些都是 `status-oled3` 已经付过学费的地方。

### 方案 B：保留初版规划值，另做一套接线 —— 否决

**否决理由**：

1. **与实物冲突**。硬件已经接成 `status-oled3` 那一套，规划值不成立。
2. **重复劳动**。要重新验证一遍 `status-oled3` 已经验证过的每一项，且没有第二台 bench 可以并行。
3. **仓库 GPIO 表分裂**。同一块板、同一批线，两个项目两套解读，排查成本上升。

### 方案 C：折中——保留键盘与编码器，仅对齐 I2C 与蜂鸣器 —— 否决

**否决理由**：键盘与编码器的引脚在 `status-oled3` 那边**根本不存在**（`status-oled3` 只有两个按钮 + 蜂鸣器 + WS2812）。用户既然选择"与 status-oled3 一致"的硬件方案，就没有再引入键盘与编码器的余地。详见 [ADR-0007](0007-two-buttons-only-input.md)。

## 决策

**本项目的硬件接口与 `status-oled3` 完全同一套，全部采用 bench 实测值：**

| 器件 | GPIO | 模式 | 有效电平 | 备注 |
|---|---|---|---|---|
| I2C SDA（PCA9548A 上游） | **5** | Wire 内部开漏 | — | **不可与 SCL 互换** |
| I2C SCL（PCA9548A 上游） | **4** | Wire 内部开漏 | — | **不可与 SDA 互换** |
| PCA9548A RESET | **8** | 推挽输出 | 低（复位） | 保留硬复位能力 |
| 按钮 A | **6** | `INPUT_PULLUP` | 低（按下接地） | 见 [ADR-0007](0007-two-buttons-only-input.md) |
| 按钮 B | **7** | `INPUT_PULLUP` | 低（按下接地） | 同上 |
| 有源蜂鸣器 | **21** | 推挽输出 | 高（通） | **有源型，只做通断** |
| WS2812 RGB | **48** | 推挽输出 | — | 板载，固定 |

同时确定：

- **蜂鸣器为有源型**，音效全部改为**通断节奏编码**（短响 / 长响 / 连续短响），不使用 PWM、不使用 LEDC、不出音阶。
- **驱动层直接复用 `status-oled3`**，接口口径以 `status-oled3/src/*.h` 为准（`pca9548a::select()` / `deselectAll()` / `screen::flush()` / `button::drain()` / `buzzer::beep()`）。
- **GPIO 38 空出**。初版把它规划给编码器按键，编码器取消后无归属，是仍可自由分配的普通 IO。
- **PCA9548A 地址 0x70** 作为目标值（成品模块最常见出厂设定），但本项目自己的模块仍需 M0 扫一次确认。

## 后果

### 正面

- 驱动层几乎全部复用，本项目的新代码量降到"游戏内核 + 两键状态机"
- 所有引脚数字都有 bench 记录，不再有"待验证规划值"
- 与 `status-oled3` 共用同一套踩坑史（线序交叉、`Wire.end()` 陷阱）
- `HARDWARE.md` 的 GPIO 表保持单一解读，跨项目可读

### 负面 / 需承担的成本

1. **取消键盘与编码器 → 交互信息密度下降**。三个主动作 + 菜单 + 调参全压在两个按钮上。这是本决策最大的代价，已在 [ADR-0007](0007-two-buttons-only-input.md) 记录，并在 [`../策划案.md`](../策划案.md) §7 列为风险最高的待验证项（第 11 项）。
2. **音效表达力受限**。有源蜂鸣器只能表达约 4 种节奏事件（按键反馈 / 动作生效 / 告警 / 成长），无法区分同长度的不同语义。
3. **本项目的 M0 从"探索"变成"复现"**。`status-oled3` 已经查过的事（地址、上拉、模块好坏）本项目不必再查，但**自己的模块批次仍要扫一次**——不同批次的成品模块跳线可能不同。

## 备注

- 完整的接口签名以 `status-oled3/src/pca9548a.h`、`screen.h`、`button.h`、`buzzer.h`、`config.h` 为准，本项目引用时**直接指过去**，不要在本项目里另抄一份签名——抄一份就会漂移。
- `status-oled3` 的 `screen.h` 有一处顺序陷阱：标题栏反色必须**先画字再整行反色**（`invertPageSpan`），先填 0xFF 再画字会让字看不见。
- 有源/无源的判别方法：直接给蜂鸣器两端通 3.3V，**响 = 有源，不响 = 无源**。此方法已由用户实测，结论为有源（`status-oled3` 侧 2026-10-16 首次测出，2026-10-21 用户在本项目再次确认是同一颗）。
- 蜂鸣器直驱电流：有源蜂鸣器典型 20–30 mA，ESP32-S3 单脚默认驱动强度 20 mA（[`../../../HARDWARE.md`](../../../HARDWARE.md) §1.2 注）。直驱可接受则不换件；音小或脚发烫则加一只 NPN 三极管驱动——**不改本决策的脚位**。
  - 📌 **2026-10-21 更新**：电流问题已由 [ADR-0010](0010-buzzer-direct-drive-needs-strongest-drive-cap.md) 查 datasheet 定案——**GPIO 21 默认档 20 mA 属临界，固件必须调 `gpio_set_drive_capability(GPIO_NUM_21, GPIO_DRIVE_CAP_3)`**（40 mA 源电流）。本条不再以"听音量 + 摸脚温"结案。
  - 📌 **2026-10-21 晚些时候**：`status-oled3` 也补齐了这一行（同一个 GPIO 21、同一颗蜂鸣器、同一个物理问题），两个项目的 `buzzer::begin()` 现在写法一致。

## 2026-10-21 M0 复现验证

本 ADR 的决策已在 M0 上板实测中逐条复现，**无一条需要修订**：

| 决策项 | M0 实测 | 结论 |
|---|---|---|
| I2C SDA=GPIO5 / SCL=GPIO4 | 三通道全部 ACK；线序未反 | ✅ 成立 |
| PCA9548A 地址 0x70 | boot report `pca9548a 0x70 : online` | ✅ 成立（无需再扫） |
| 按钮 A=GPIO6 / B=GPIO7 | 4 种手势全部触发，一次按压一次事件 | ✅ 成立 |
| 有源蜂鸣器 GPIO21，HIGH 响 | 5 种节奏用户确认全部可分辨 | ✅ 成立 |
| 驱动强度须提到 `GPIO_DRIVE_CAP_3` | `gpio_get_drive_capability()` **现场读回 = 3** | ✅ 成立（见 [ADR-0010](0010-buzzer-direct-drive-needs-strongest-drive-cap.md)） |
| PCA9548A RESET 接 GPIO 8 | 未接/未用亦不影响（本项目固件不驱动 RST） | ⚠️ 接线保留，本轮未实测复位功能 |

> 📌 **负面第 3 条已消化**：「自己的模块批次仍要扫一次」这件事在 M0 里**做了**——扫描结果 0x70，与 `status-oled3` 同址。
>
> 📌 **负面第 1 条已消化**：两键信息密度风险（`../策划案.md` §7 第 11 项）已由 [ADR-0009](0009-two-button-interaction-coverage.md) 结构化闭合，**残余验证移入 M4 试玩**。
>
> 📌 **本 ADR 未提及但被 M0 验证的**：PCA9548A RESET（GPIO 8）的硬复位功能本轮**没有实测**——固件不驱动该脚。`status-oled3` 侧记录过「驱动低再释放无效」，结论是 RST 只是留作兜底、不作为常规路径。
