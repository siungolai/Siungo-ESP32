# 2. 一次只选通一个通道，不做并发广播

日期：2026-10-15

## 状态

已接受

## 背景

PCA9548A 的核心卖点是**多通道并发**——控制寄存器的 1 字节里每一个 bit 对应一路，可以任意组合同时选通（TI 数据手册："Any individual SCx/SDx channel or combination of channels can be selected"）。

对本项目，最直接的诱惑是：**三块屏的通道同时选通，然后把同一帧广播出去**，理论上三块屏一次刷完。

本文记录为什么**主动放弃**这个能力。

## 考虑的方案

### 方案 A：三通道并发，广播刷新

同时选通通道 0/1/2，一次 I2C 写入三块屏都收到。

**理论上**：三块屏都保持 0x3C，广播写入确实会被三块同时接收——地址相同反而成了"特性"。

**否决理由**：

1. **上拉并联风险（主要理由）**
   SSD1306 模块自带板载上拉（本机已实测确认，见 `../../../HARDWARE.md:159-161`），常见值 4.7k~10k。
   - 三路各 4.7k 并联 ≈ **1.57k**
   - 若 PCA9548A 模块本身也在各通道挂了 10k（八路全上拉型模块），并联值会掉到 **< 1k**
   - 多数 SSD1306 的低电平驱动能力标称 sink 约 3mA，上拉过强会让低电平无法拉到位
   
2. **无法做故障隔离**
   三块屏接在同一逻辑线上，任一块拉死总线（I2C 经典的 bus stuck 故障），**三块全废**。而一次一路时，某通道卡死只影响那一块。

3. **广播不可观测**
   广播写入拿不到每块屏的应答，无法知道哪块屏在线、哪块刷失败了。这对一个"三块屏可能来自不同批次"的 DIY 项目是实际痛点。

4. **无法逐屏差异化**
   本方案三块屏显示**不同内容**（角色/数值/日志），本来就必须分别写入。广播只对"三屏显示同样内容"有意义——而这不是本项目需求。

5. **刷新调度反而变复杂**
   广播要求三块屏的刷新时机完全同步，而本方案刻意让三块屏有不同刷新频率（见 [ADR-0003](0003-screen-role-split.md)）。强行同步会抵消分层调度带来的总线节省。

### 方案 B：一次只选通一路，顺序刷新 —— 采纳

`选通道 → 刷屏 → 断开 → 下一路` 的严格顺序流程，任何时刻最多一路导通。

**采纳理由**：

1. **上拉负载可控**：任一时刻只有一块屏的上拉在线，不存在并联
2. **故障隔离**：某通道总线卡死不影响其他通道；配合 RESET 脚可单独恢复
3. **可观测**：每次写入都有独立的 `endTransmission()` 结果码，能精确知道哪块屏掉线
4. **天然支持差异化刷新**：三块屏可以有不同的刷新频率，完全独立
5. **调度简单**：一个不需要并发的顺序流程，没有竞争条件

## 决策

**每个时刻最多选通一个通道。** 驱动层不提供"多通道位掩码"接口，只提供：

```cpp
bool pca9548a_select(uint8_t channel);   // 只选通这一个，其余全断
bool pca9548a_deselect_all();
```

刻意**不暴露** `pca9548a_write_mask(uint8_t mask)` 这样的接口，从 API 层面杜绝误用。

## 后果

### 正面

- 上拉负载可预测，不会随选通组合变化
- 故障隔离 + 逐通道可观测
- 三块屏可独立调度

### 负面 / 需承担的成本

1. **放弃并发吞吐**。三块屏要顺序刷，理论刷新率是并发方案的 1/3
2. **换通道有开销**。每次切换通道需要一次独立的 I2C 事务（写控制寄存器），约 1 字节 @400kHz
3. **必须做通道缓存**，否则上层频繁 `select()` 会产生大量无用事务

### 对成本 2、3 的缓解：通道缓存

驱动内部记住当前选通通道，`select(n)` 时若 `n == 当前通道` 则**直接返回，不产生任何 I2C 事务**。这样上层可以放心在每个绘制调用前都写一次 `select()`。

### 对成本 1 的评估

本方案三块屏的刷新频率本就分层（日志事件驱动、数值 2–5Hz、角色 1–2Hz，见 [ADR-0003](0003-screen-role-split.md)），绝大多数 tick 里**只有一块屏需要刷新**。顺序刷新带来的吞吐损失在实际工作负载下几乎无感。

## 备注

- 上拉并联的具体数值取决于 SSD1306 模块的实际上拉值，已在 [`../策划案.md`](../策划案.md) §7 列为待验证项
- 若未来真的需要刷 8 块屏且并发成为瓶颈，重新评估的前提是：**先实测多通道并发时的低电平电平余量**，不能凭规格书假设
