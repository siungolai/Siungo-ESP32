# 1. 用 PCA9548A 解决三块同址 SSD1306

日期：2026-10-15

## 状态

已接受

## 背景

设备需要三块 SSD1306 OLED。SSD1306 的 7-bit I2C 地址**只由模块上的地址电阻决定**，出厂只有 **0x3C**（少数模块 0x3D）两个选项。I2C 是总线拓扑——所有器件并联在同一条 SDA/SCL 上，靠地址区分。

因此三块屏若挂在同一条总线上，会有**至少两块地址相同，无法被区分**。

关键澄清：**换 GPIO 解决不了这个问题**。I2C 有总线概念，换引脚只改变"总线接在哪两个脚"，不改变"总线上有两个同地址器件"这一事实。

## 考虑的方案

### 方案 A：强制劈地址

把两块屏的地址电阻改焊到 0x3D。

**否决理由**：SSD1306 只有 0x3C / 0x3D **两个**地址，所以这个方案**最多支持两块屏**，第三块无解。且需要动烙铁，有损坏风险。

### 方案 B：I2C 多路复用器（PCA9548A）—— 采纳

一根上游总线进 PCA9548A，8 路下游通道出。三块屏分别挂在通道 0/1/2，**每块屏保持出厂 0x3C 地址**——因为每条通道上只有一个 0x3C 器件，冲突在通道层面被隔离。

**采纳理由**：
1. **完全不需要改硬件**，三块屏保持出厂状态
2. **可扩展到 8 块屏**，通道 3–7 是白送的扩展位
3. 上游地址由 A0/A1/A2 决定，0x70 占住后未来加器件**不会撞地址**
4. 支持热插拔（TI 数据手册明确支持 hot insertion），调试时不必断电
5. 有 **active-low RESET 脚**，下游总线卡死时可硬复位——这是多总线方案没有的恢复手段
6. 已在用户购买清单内

### 方案 C：两组独立 I2C 总线

I2C0 带一块屏，I2C1 带两块（那两块仍需劈一块地址）。

**否决理由**：仍然要改硬件，且第三块屏本质未解决。相比 B 没有任何优势。

### 方案 D：三组独立 I2C 总线

每块屏独占一条总线，地址全保持 0x3C，纯软件解决。

**技术上是可行的**——已核实 ESP32-S3 的 I2C 可映射到任意 GPIO（见 `soc/gpio_sig_map.h`：I2C0 只反向映射到 `GPIO_MATRIX_CONST_ZERO`/`ONE`，即无固定脚位，必须过 GPIO Matrix），不需要改硬件。

**否决理由**：占用 **6 个 GPIO**（3 × SDA/SCL），而方案 B 只占 **2 个**。且用户已购买 PCA9548A。若未购买，D 方案（零额外芯片）会是有力竞争者——**这是本决策唯一的前提依赖**。

## 决策

采用 **方案 B：PCA9548A，三块屏挂通道 0/1/2，全部保持 0x3C 出厂地址**。

## 后果

### 正面

- 零硬件改造，三块屏开箱即用
- 5 个空闲通道可供未来扩展
- 单条上游总线只占 2 个 GPIO

### 负面 / 需承担的成本

1. **多一颗芯片**，且需要软件驱动它（约 50 行）
2. **上拉电阻归属变复杂**：TI 数据手册明确「每条被启用的下游通道需各自外部上拉」，PCA9548A 不带内部上拉。本次核查确认上游由模块自带 10k 覆盖、下游由 SSD1306 板载覆盖，但**上游与下游是两件独立的事**，不可互相推导
3. **必须处理"上电默认全断开"**：TI 明确 power-up 时所有通道 deselect，复位后也如此。启动流程里必须有一步显式选通
4. **上拉并联风险**：若多通道同时选通，各支路上拉会并联（详见 [ADR-0002](0002-single-channel-sequential-refresh.md)）

## 备注

- PCA9548A 数据手册：TI PCA9548A Low Voltage 8-Channel I2C Switch with Reset (Rev. G)
- 已核实规格：8 通道、地址由 A0/A1/A2 决定、上电全 deselect、400kHz 上限、active-low RESET、无内部上拉
- 本机 SSD1306 板载上拉已由 [`../../../HARDWARE.md:159-161`](../../../HARDWARE.md) 实测确认（`pullup=HIGH float=HIGH`）
