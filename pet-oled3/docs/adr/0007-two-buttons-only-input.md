# 7. 只用两个按钮做全部输入，取消 4x4 键盘与旋转编码器

日期：2026-10-21

## 状态

已接受

## 背景

初版策划案（2026-10-15）的输入方案是**4x4 矩阵键盘 + 旋转编码器**：

| 器件 | 规划用途 |
|---|---|
| 4x4 矩阵键盘（行 GPIO 10–13、列 GPIO …） | **三个主动作各占一键**（喂食 / 玩耍 / 休息），另有数字键供菜单与调参 |
| 旋转编码器（A/B 相 + 按键，GPIO 38 规划给按键） | 调参、翻页、"按下=确认" |

初版策划案自己就把"4x4 键盘到底是矩阵（8 线）还是 TM1650 之类 I2C 编码键盘（4 线）"列为**动手前必须确认的高风险项**（[`../策划案.md`](../策划案.md) §7 第 5 项）——因为若是后者，它会占用一个 I2C 地址、挂到 PCA9548A 的空闲通道上，**整个拓扑要改**。

2026-10-21，用户决策：**输入方案与 `status-oled3` 一致，只用两个按钮**（`status-oled3` 的实物就是两个轻触开关 + 一个有源蜂鸣器 + 板载 WS2812，没有任何键盘或编码器）。这与 [ADR-0006](0006-hardware-interface-aligned-with-status-oled3.md) 的硬件接口统一决策同源。

`status-oled3` 那边已经验证过的两键交互模式：

- 消抖用 4 态状态机（`idle → debounce_down → down → debounce_up → idle`），**按压与释放各采样一次**，状态变化须持续满 20 ms 才接受
- **一次按下一次事件**：短按在**释放时**发一次 `EVENT_SHORT_PRESS`；长按在**跨过 1000 ms 阈值的那一刻**发一次 `EVENT_LONG_PRESS`，释放时不再补发
- `tick()` 每轮 `loop()` 调一次、立即返回，**不阻塞**（不用 `delay()`，避免拖慢刷新节拍）
- 键位语义随**上下文**变化（`status-oled3` 里按钮 A = 翻页、按钮 B = 换聚焦屏）

## 考虑的方案

### 方案 A：保留键盘 + 编码器 —— 否决

**否决理由**：

1. **与硬件统一决策冲突**。用户已经选择"硬件接口与 `status-oled3` 一致"，而 `status-oled3` 的实物里没有键盘也没有编码器。文档不能记录一条实物上不存在的接线。
2. **没有实物可接**。初版规划值（GPIO 10–13 等）从未在本机验证过，现在也没有器件。
3. **初版最大的拓扑风险随之消失**。键盘是矩阵还是 TM1650 编码型这个未决项**不再存在**——没有键盘，就不占用 I2C 地址，拓扑不再有变数。

### 方案 B：三个按钮（两键 + 一个备用）—— 未采纳（但留了位置）

**未采纳理由**：硬件统一决策明确是"与 `status-oled3` 一致"，即**两个**按钮。多加一个按钮会让本项目的实物与 `status-oled3` 不一致，收益（多一个键）不足以抵消这次统一的核心价值。

**但保留位置**：**GPIO 38 现在空着**（初版规划给编码器按键，编码器取消后无归属）。若试玩下来两键不够用，最小改动是**加一个第三键到 GPIO 38**，不动任何其他设计。已登记为 [`../策划案.md`](../策划案.md) §7 第 11 项（风险最高的待验证项）。

### 方案 C：只用两个按钮 + 上下文相关的键位语义 —— 采纳

两个按钮驱动全部交互，靠的是**同一个上下文里按钮含义会变**。

**采纳理由**：

1. **与实物一致**。硬件已定，两键是既成事实。
2. **交互密度可以靠上下文补回来**。养成游戏的核心是"看数值 → 选一个动作 → 执行"，日常操作只有三个主动作，**主界面直接用光标循环就能覆盖**，不需要按键矩阵。
3. **"退出"靠长按而不是第三键**。`status-oled3` 已经把长按做进 `button` 驱动（阈值 1000 ms），本项目直接继承。
4. **复用了已验证的状态机**。消抖、一次按下一次事件、长按不发两次——这些在 `status-oled3` 已经跑通，不需要自己写。
5. **保留了升级路径**。两键不够用时的最小改动是加 GPIO 38 第三键，而不是重做输入层。

## 决策

**本项目的全部输入来自两个轻触按钮**（GPIO 6 = 按钮 A、GPIO 7 = 按钮 B，`INPUT_PULLUP`，按下接地为低电平）。**取消 4x4 矩阵键盘与旋转编码器。**

### 键位语义（上下文相关）

| 上下文 | 按钮 A（GPIO 6） | 按钮 B（GPIO 7） | 长按 A | 长按 B |
|---|---|---|---|---|
| **主界面**（默认） | 在 **喂食 / 玩耍 / 休息** 三个动作间移动光标 | **执行**当前光标动作 | **进菜单** | —（不绑定） |
| **菜单** | 光标下移 | **确认 / 切换** | —（不绑定） | **返回上一级** |

- 光标默认停在**角色屏**（通道 0），当前选中项高亮反色显示
- **执行动作后光标不移动**——玩家可以连按同一个动作（常见于连续喂食）
- **长按 B = 返回**：两键没有第三个键，"退出"必须靠长按
- **长按 A = 进菜单**：本 ADR 初版只写了"长按 B = 返回"，**没写怎么进菜单**——该缺口由 [ADR-0009](0009-two-button-interaction-coverage.md) 补上

> 📌 **2026-10-21 订正（本表两处）**：
>
> 1. **「进菜单」由长按 A 承担**（本 ADR 初版遗漏）。完整的 2 上下文 × 2 键 × 2 按压型 = **8 种手势组合全部有归属**（6 绑定 + 2 明确不绑定），见 [ADR-0009](0009-two-button-interaction-coverage.md)。**长按与短按不双触发**由 `button::drain()` 保证。
> 2. **上下文名「菜单 / 数值调校」应改为「菜单」**。**调参已移出运行时 UI**（改为编译期常量 / NVS），菜单里只剩「静音开关」「关于本机」两项二元项——见 [ADR-0009](0009-two-button-interaction-coverage.md)。这是本 ADR 负面第 2 条的直接落实。

### 复用与新增

| 部分 | 来源 |
|---|---|
| 消抖状态机、一次按下一次事件、长按阈值 | ✅ 直接复用 `status-oled3/src/button.{h,cpp}`（`BUTTON_DEBOUNCE_MS=20`、`BUTTON_LONGPRESS_MS=1000`） |
| 键位语义、上下文切换、光标移动、动作分发 | ⭕ **本项目新写**（`status-oled3` 的语义是翻页/换屏，与养成游戏无关） |

> 📌 **复用时必须改的一处**：`status-oled3` 的 `button::ButtonId` 枚举名是 `BTN_PAGE`（翻页）与 `BTN_FOCUS`（换聚焦屏），**带着状态显示器的语义**。本项目把它们改成 `BTN_A`（选动作 / 光标下移）与 `BTN_B`（确认 / 执行）——**驱动逻辑照抄，枚举名与语义重写**。不要把 `status-oled3/src/main.cpp` 的按钮处理逻辑一起搬过来。
>
> 📌 **2026-10-21 实现现状（与初版不同）**：M0 固件 `pet-oled3/src/main.cpp` 实际**沿用了 `status-oled3` 的枚举名** `BTN_PAGE` / `BTN_FOCUS`（`config.h` 里也是 `PIN_BUTTON_PAGE` / `PIN_BUTTON_FOCUS`），**没有**改成本 ADR 设想的 `BTN_A` / `BTN_B`。理由：`button` 驱动是整份复制过来的，改枚举名要动 `button.h` / `button.cpp` / `config.h` / `main.cpp` 四处，而**语义归属由上层的动作分发决定**——`main.cpp` 里 A 键映射到"移动光标/进菜单"、B 键映射到"执行/确认/返回"，与 `status-oled3` 的"翻页/换屏"无关。**枚举名是历史包袱，不是行为差异**。若将来重命名，四处一起改，别只改一处。

## 后果

### 正面

- 实物与文档一致，无"规划但不接线"的悬空器件
- 输入层不需要新写驱动，消抖与长按行为已被 `status-oled3` 验证
- 拓扑风险（键盘是否 I2C 器件）彻底消失
- 升级路径明确：不够用就加 GPIO 38 第三键

### 负面 / 需承担的成本

1. **信息密度显著下降**。三个主动作 + 菜单 + 调参全压在两个键上，比"每动作一键 + 数字键"的键盘方案**操作步骤更多**。**这是本决策最大的代价。**
2. **调参变笨**。编码器可以连续增减，菜单只能"上/下"逐档。数值调校（成长阈值、衰减速率）若要频繁调整会很累——因此设计上应把这些参数**放进 NVS 或编译期常量**，而不是做成运行时菜单。
3. **依赖长按作为"退出"**。长按有 1000 ms 延迟，快速操作时会感觉"退不出去"。缓解办法是把返回放在**不常用的层级**上，日常路径不经过它。
4. **"连按同一个动作"必须可行**。若每执行一次就跳回菜单，连续喂食会变成灾难。因此 §4.4 规定执行后光标不动。
