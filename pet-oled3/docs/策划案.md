> ⚠️ **蜂鸣器必须是无源压电式**。有源蜂鸣器只能发出单一固定频率，无法演奏旋律、无法做音效渐变。若手上是有源蜂鸣器，见 §7 待验证清单。

### 2.2 为什么不直接并联三块屏

三块 SSD1306 出厂地址**都是 0x3C**，I2C 是总线拓扑——所有器件并联在同一条 SDA/SCL 上靠地址区分，**换 GPIO 解决不了**（换脚只改变"总线接在哪两个脚"，不改变"总线上有两个同地址器件"）。

四种候选方案与选择理由：

| 方案 | 做法 | 判定 |
|---|---|---|
| A. 强制劈地址 | 每块屏把地址电阻改焊到 0x3D | ❌ 只能得到**两块**，第三块无解 |
| **B. I2C 多路复用器** | PCA9548A，屏分别挂 0/1/2 通道 | ✅ **已选**，见 [ADR-0001](adr/0001-use-pca9548a-for-three-displays.md) |
| C. 两组 I2C 总线 | I2C0 一块，I2C1 两块（仍需劈一块地址） | ❌ 仍要改硬件，且第三块仍是问题 |
| D. 三组 I2C 总线 | 每块屏独占一条总线 | ❌ 可行但耗 6 个 GPIO，且已购 PCA9548A |

**PCA9548A 的关键规格**（TI 官方数据手册）：

| 项目 | 事实 |
|---|---|
| 通道数 | 8 路双向开关（1-of-8） |
| 通道选择 | **每路可独立选，也可任意组合同时选** |
| 从机地址 | **7-bit，由 A0/A1/A2 三个硬件脚决定**，一条总线最多挂 8 片 |
| 上电默认 | **所有通道 deselect**（复位/上电后必须软件激活） |
| 供电 | 2.3–5.5V，可在 1.8/2.5/3.3/5V 间电平转换，I/O 5V 耐压 |
| 频率上限 | **400 kHz** |
| RESET 脚 | **active-low**，可硬件复位（下游总线卡死时的救命通道） |
| 上拉 | **不带内部上拉**，每条被启用的下游通道需各自外部上拉 |

### 2.3 上拉电阻核对（已确认，勿重复加）

PCA9548A 与 SSD1306 的上拉归属，两件事必须分开看：

| 位置 | 上拉来源 | 依据 | 结论 |
|---|---|---|---|
| 上游 ESP32 ↔ PCA9548A | PCA9548A 模块板载 10k | 用户确认（成品模块，带 10k） | ✅ 不需再加 |
| 下游 通道 0/1/2 ↔ 三块屏 | **SSD1306 模块板载** | [`HARDWARE.md`](../../HARDWARE.md) §3.5 实测 `pullup=HIGH float=HIGH` | ✅ 不需再加 |

> ⚠️ **禁止项**：不要再往 SDA/SCL 上补 4.7k。上游已有 10k、下游每块屏自带，重复并联会把等效阻值拉得过低，反而增加低电平驱动负担。
>
> 📌 `HARDWARE.md` 那个实测只证明**屏那一侧**有上拉，**不证明 PCA9548A 上游有上拉**。本次是模块自带的 10k 覆盖了上游，两件事互相独立。

### 2.4 为什么"一次只选通一路"

PCA9548A **支持**多通道并发（这是它的卖点），但本方案**主动不用**：

1. **上拉并联风险**：三块屏的板载上拉（常见 4.7k~10k）若在通道 0/1/2 上同时导通，会并联。3 × 4.7k ≈ **1.57k**；若模块本身也在各通道挂了 10k，并联值会掉到 **< 1k**，逼近多数 SSD1306 的低电平驱动极限（标称 sink 3mA）。
2. **故障隔离**：一次一路，某块屏坏了或该通道总线卡死，**不影响**另外两块。
3. **调度可预测**：不需要处理"广播时谁来应答"的问题。
4. **时序简单**：`选通道 → 刷屏 → 断开 → 下一路`，是一个不需要并发的顺序流程。

见 [ADR-0002](adr/0002-single-channel-sequential-refresh.md)。

## 3. 接线表

### 3.1 I2C 总线（PCA9548A 上游）

| PCA9548A 排针 | ESP32-S3 | 说明 |
|---|---|---|
| SDA | **GPIO 8** | 上游数据 |
| SCL | **GPIO 9** | 上游时钟 |
| VCC | 3V3 | 3.3V 供电（模块支持 2.3–5.5V） |
| GND | GND | |
| A0 / A1 / A2 | GND（跳线到底） | 决定上游地址，见 §3.3 |
| RESET | 3V3（或悬空，见注） | active-low，拉低复位 |

> **RESET 处理**：多数成品模块已把 RESET 通过上拉电阻拉到 VCC，"悬空"即不复位。若要保留"下游总线卡死时硬复位"的能力，可把它接到一个空闲 GPIO 由软件拉低。**bringup 阶段先悬空**，验证通过后再决定是否占用一个 GPIO。

### 3.2 三块屏（PCA9548A 下游）

| 通道 | 器件 | SCx | SDx | VCC | GND |
|---|---|---|---|---|---|
| **0** | SSD1306 屏 1（角色屏） | SC0 | SD0 | 3V3 | GND |
| **1** | SSD1306 屏 2（数值屏） | SC1 | SD1 | 3V3 | GND |
| **2** | SSD1306 屏 3（日志屏） | SC2 | SD2 | 3V3 | GND |
| 3–7 | 预留扩展位（见 §3.4） | — | — | — | — |

三块屏**全部保持出厂 0x3C 地址**，因为每条通道上只有一个 0x3C 器件，地址冲突在通道层面被隔离。

### 3.3 PCA9548A 上游地址

7-bit 地址 = `1110 A2 A1 A0`：

| A2 A1 A0 | 7-bit 地址 | 8-bit 写地址 |
|---|---|---|
| **0 0 0** | **0x70** | 0xE0 |
| 0 0 1 | 0x71 | 0xE2 |
| … | … | … |
| 1 1 1 | 0x77 | 0xEE |

**默认目标：A0/A1/A2 全接地 → 0x70**（成品模块最常见的出厂设定）。

> ⚠️ 成品模块的地址跳线可能是**焊死的也可能是可拨的**，且不一定遵守"全接地=0x70"。**bringup 第一步必须用 I2C 扫描确认实际地址**，不要硬编码猜测值。

### 3.4 预留扩展位

通道 3–7 空置。0x70 已占住，未来加器件**不会撞地址**，可挂：环境光传感器、EEPROM（存档）、第二编码器、甚至第 4/5/6 块屏。**现在不决定。**

### 3.5 GPIO 分配总表

| 功能 | GPIO | 备注 |
|---|---|---|
| I2C SDA（上游） | 8 | 避开 1/2，见下 |
| I2C SCL（上游） | 9 | 同上 |
| 键盘 行 1–4 | 10, 11, 12, 13 | 逐行扫描 |
| 键盘 列 1–4 | 14, 15, 16, 17 | 需内部上拉 |
| 编码器 A 相 | 18 | 中断输入 |
| 编码器 B 相 | 21 | 中断输入 |
| 编码器 按键 | 38 | 内部上拉 |
| 蜂鸣器 | 38–47 中取一个空闲脚 | **待定**，见 §7 |
| WS2812 RGB | 48 | **板载，固定** |

> 🚫 **硬约束 1：I2C 绝不能接 GPIO 1 / GPIO 2。** [`HARDWARE.md`](../../HARDWARE.md) §6.1 记录：OLED 接 GPIO1(SCL)/GPIO2(SDA) 时，`i2c-scan` 全段每个地址 `endTransmission` 返回 **5（超时）**，换上 GPIO4/GPIO5 立刻通。不要重试这条死路。
>
> 🚫 **硬约束 2：避开 GPIO 19 / 20。** 这两个是原生 USB D+/D-（USB-Serial-JTAG）。[`HARDWARE.md`](../../HARDWARE.md) §1.1 记载本机靠板载原生 USB 下载调试，占用即失去串口。
>
> ⚠️ **硬约束 3：避开 GPIO 0 / 3 / 45 / 46 等 strapping 脚**，以及 SPI0/1 flash 占用脚（26–32 等）。上表已避开。
>
> 📌 上表的 GPIO 10–18 / 21 / 38 是**建议值**，全部为普通 IO。ESP32-S3 的 I2C 可映射到任意 GPIO（已核实：`gpio_sig_map.h` 中 I2C0 只反向映射到 `GPIO_MATRIX_CONST_ZERO`/`ONE`，即**无固定脚位**，必须过 GPIO Matrix），换脚只改常量。**最终值待 bringup 实测确认。**

## 4. 玩法设计

### 4.1 核心循环

```
        ┌─────────────────────────────────────────┐
        │                                         │
        ▼                                         │
  数值随时间下降 ──► 角色表情变差 ──► 玩家察觉 ──► 按动作键
    (每秒 tick)      (屏 1 反馈)     (看屏 1/2)   (喂食/玩耍/休息)
                                                      │
                                                      ▼
                                              数值回升、亲密度变化
                                                  (屏 2/3 反馈)
```

### 4.2 三条数值

| 数值 | 含义 | 下降 | 回升手段 | 副作用 |
|---|---|---|---|---|
| **饱食度** | 肚子饿不饿 | 持续 | **喂食**（键 1） | 过饱会掉心情 |
| **心情** | 开不开心 | 中期 | **玩耍**（键 2） | 玩耍消耗体力 |
| **体力** | 累不累 | 玩耍时加速 | **休息**（键 3） | 休息时心情缓慢下降 |

三条数值**互相牵制**，构成决策张力：不能一直喂（过饱掉心情）、不能一直玩（体力耗尽）、不能一直睡（心情下滑）。

### 4.3 成长阶段

单角色从幼体养到成体，阶段由**累计存活时间 + 亲密度**共同决定：

| 阶段 | 进入条件 | 屏 1 表现 |
|---|---|---|
| 卵 | 初始 | 静止，偶尔晃动 |
| 幼体 | 存活 > 5 分钟 | 小尺寸角色图，动作简单 |
| 成体 | 存活 > 30 分钟且亲密度达标 | 大尺寸角色图，表情丰富 |
| 衰老 | 存活 > 2 小时 | 动作迟缓 |

> 具体阈值是**待调的数值**，见 §7。上表只定结构，不定平衡。

### 4.4 输入映射

**4x4 键盘**（16 键，`HARDWARE.md` 无占用冲突）：

| 键区 | 功能 |
|---|---|
| 键 1–3 | **喂食 / 玩耍 / 休息**（三大主动作） |
| 键 4 | 切换屏 3 的日志视图 / 菜单 |
| 键 5–8 | 预留（未来：状态详情、设置、存档） |
| 键 9–16 | 预留（数字输入 / 快捷槽位） |

**旋转编码器**：

| 操作 | 功能 |
|---|---|
| 旋转 | 调节选中项（数值微调 / 菜单光标 / 日志滚动） |
| 按下 | 确认 / 切换焦点屏 |

**蜂鸣器**（无源压电）：

| 时机 | 声音 |
|---|---|
| 按键 | 短促点击音 |
| 数值告警 | 下降过阈值的警示音 |
| 成长阶段升级 | 上行旋律 |
| 角色不悦 | 低沉的拒绝音 |

**WS2812 RGB**（GPIO48 板载）：

| 状态 | 颜色 |
|---|---|
| 一切正常 | 缓慢呼吸的绿色 |
| 数值告警 | 黄色闪烁 |
| 角色不悦 | 红色脉冲 |
| 成长/升级 | 快速彩虹 |
| 开机自检 | 白→蓝→灭 |

### 4.5 时间推进

**仅开机时间推进，关机暂停。** 用 `millis()` 累积，不联网、不接 RTC。

- ✅ 优点：无 WiFi 协议栈开销（[`HARDWARE.md`](../../HARDWARE.md) §9 记录 WiFi 会让 RAM 涨到 14.1%、Flash 涨到 21.5%）、无外设、调试简单、时间流速恒定可测
- ⚠️ 代价：断电即回到"上次没攒下任何进度"，**没有离线成长**

见 [ADR-0004](adr/0004-uptime-only-time-progression.md)。

### 5.1 分层

### 5.2 PCA9548A 驱动设计

极简，只需两个操作：

```cpp
// 选通一个通道（其余全部断开）
bool pca9548a_select(uint8_t channel);   // channel 0-7

// 全部断开（换通道前、异常恢复时用）
bool pca9548a_deselect_all();
```

**控制寄存器**：向 0x70 写 1 字节，bit N = 1 表示选通通道 N。`pca9548a_select(2)` 即写 `0x04`。

**关键设计：通道缓存**。驱动内部记住当前选通的是哪个通道，`select()` 时若目标通道 == 当前通道则**直接返回，不产生 I2C 事务**。这样上层可以放心地在每个绘制调用前都写一次 `select()`，不会浪费总线。

### 5.3 显示层接口

三块屏**共用同一个 `ssd1306_i2c` 驱动**，靠通道切换复用：

```cpp
class Display {
  bool begin(uint8_t channel);   // 初始化时探测该通道上的屏
  void flush();                  // 把 1KB 显存刷到当前通道的屏
};
```

**必须实现的保护**（源自 [`HARDWARE.md`](../../HARDWARE.md) §6.2 的实测教训）：

> 下游器件不在线时，`flush()` 发 8 页 × 2 次 I2C 事务，每次 `endTransmission()` 阻塞到 **50ms 超时**，一轮刷新近 **800ms**，足以把 1 秒的节拍带偏。

**三块屏 + PCA9548A 意味着这个坑放大三倍。** 因此：

1. **每通道独立探测**：启动时逐通道探测，记录哪些屏在线
2. **离线即跳过**：某通道的屏不在线，该通道的 `flush()` 立即返回，**不做任何 I2C 事务**
3. **节拍解耦**：游戏 tick 用 `millis()`，**与屏幕在线状态完全解耦**。即使三块屏全掉线，游戏逻辑仍以精确 1Hz 推进

### 5.4 刷新调度

三块屏按**信息变化频率**分层，这是本方案的调度核心：

| 屏 | 角色 | 刷新频率 | 触发方式 |
|---|---|---|---|
| 屏 3（日志） | 事件滚动、菜单、提示 | **事件驱动**（变化时刷） | 最高优先级，事件立即刷 |
| 屏 2（数值） | 三条数值条 + 数字 | **2–5 Hz** | 定时，数值平滑动画 |
| 屏 1（角色） | 大图 + 表情 | **1–2 Hz** | 低频，仅状态变化时刷 |

**轮询顺序**：`日志 → 数值 → 角色`。每轮最多刷一块屏（有实际变化的那块），避免三屏同时刷把总线占满。

**为什么这样分**：养成游戏的信息有时间维度——角色图变化最慢（看表情就知道状态）、数值变化中等（要看到条在涨）、日志变化瞬时（要看到刚发生了什么）。按变化频率分层，天然形成调度优先级。

| 无源蜂鸣器 PWM | 需新写（`ledcWriteTone` 或 LEDC） | ⭕ 新增 |

> ⚠️ **字模方向必须与显存一致**：[`HARDWARE.md`](../../HARDWARE.md) §2.2 记录「1 字节 1 列，bit0 = 页内最上一行」。替换字库时务必对齐，否则字会显示成乱块。
> 三份裸驱的完整接口（常量、构造、方法签名、时序常量）见 [`HARDWARE.md`](../../HARDWARE.md) §2.6 / §3.6 / §5.2，不要凭记忆调用。

## 6. 里程碑

按 **bringup 优先** 排（Q19 决策，见 [ADR-0005](adr/0005-bringup-first.md)）。

### M0 · 硬件 bringup（**阻塞项，必须先完成**）

目标：证明 PCA9548A + 三块屏这条链路真的通。

- [ ] 扫 I2C 总线，确认 PCA9548A 实际地址（期望 0x70，**以扫描结果为准**）
- [ ] `pca9548a_select()` / `deselect_all()` 生效验证
- [ ] 逐通道探测：通道 0/1/2 上能否各自找到 0x3C
- [ ] 三块屏分别点亮并显示**不同内容**（同屏内容无法区分是否真的切换成功）
- [ ] 记录：`endTransmission()` 是否有返回 5（超时）
- [ ] 确认 GPIO 分配表（§3.5）中建议值在本机可用
- [ ] 把 M0 结论回写 [`HARDWARE.md`](../../HARDWARE.md) §4（§4.8 的 bringup 清单逐条勾掉，规划接口改为实测接口）

**验收标准**：三块屏能显示三个不同的字符串，且任意时刻单独刷新其中一块不干扰另外两块。

## 7. 待验证清单

**这些是策划阶段无法确定、必须在动手时确认的事项。** 不要当成已知事实。

| # | 待验证项 | 为什么不确定 | 验证方法 | 影响 |
|---|---|---|---|---|
| 1 | **PCA9548A 实际地址** | 成品模块跳线可能焊死，不一定遵守"全接地=0x70" | I2C 扫描 0x70–0x77 | 硬编码地址会直接失败 |
| 2 | **PCA9548A 模块上拉位置** | 只知道"有 10k"，不知道挂在上游还是八路全挂 | 万用表量各通道 SDA/SCL 对 VCC 阻值 | 决定是否触发上拉并联风险（§2.4） |
| 3 | **蜂鸣器类型** | 未确认是有源还是无源 | 接 3.3V 直接通电：响=有源，不响=无源 | 有源则无法做音效渐变，需换件 |
| 4 | **蜂鸣器 GPIO** | 上表留空，需与键盘/编码器脚位统筹 | 待 §3.5 表定稿 | — |
| 5 | **4x4 键盘是矩阵还是编码** | 4x4 键盘有"矩阵 8 线"和"带编码芯片(如 TM1650)"两种 | 数排针数量：8 根=矩阵，4 根=编码 | 编码型是 I2C 器件，会占用 PCA9548A 通道！ |
| 6 | **编码器是否带按键** | 影响能否用"按下=确认" | 看排针数量：5 脚=带按键，3 脚=不带 | 决定交互设计 |
| 7 | **上游 SDA/SCL 用 GPIO 8 / GPIO 9 是否可用** | [`HARDWARE.md`](../../HARDWARE.md) §4.5 是建议值，未在本机验证 | 按建议值接线后扫总线 | 冲突则换脚，改 §4.5 与 §3.5 两处 |
| 8 | **三块屏是否同一型号尺寸** | 0.96"/1.3" 的显存模型相同但物理尺寸不同 | 目视 | 影响外壳与布局 |
| 9 | **SPI0/1 与 strapping 脚完整清单** | §3.5 已避开常见项，但未逐脚核对本机 | 查 ESP32-S3 datasheet + 实测 | 引脚冲突 |
| 10 | **数值平衡参数** | 需要试玩才能定 | 试玩迭代 | 只影响手感，不影响架构 |

> ⚠️ **第 5 项特别重要**：如果 4x4 键盘是 **TM1650 之类的 I2C 编码键盘**，它会占用一个 I2C 地址，需要挂到 PCA9548A 的空闲通道上（或与屏共用通道，但要注意地址不冲突）。这会改变整个拓扑。**动手前先确认。**

## 8. 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| GPIO1/2 上 I2C 不通（已实测） | 已规避 | §3.5 已避开 1/2；见 [`HARDWARE.md`](../../HARDWARE.md) §6.1 |
| 占用 GPIO19/20 失去 USB 串口 | 已规避 | §3.5 已避开 |
| 三块屏并联合并上拉导致驱动不足 | 中 | §2.4 一次只选通一路 |
| 某块屏离线导致整轮刷新阻塞 800ms | **高** | §5.3 每通道独立探测 + 离线立即返回 |
| PCA9548A 下游总线卡死 | 中 | RESET 脚可硬复位（§3.1）；bringup 阶段先验证能否复现 |
| 蜂鸣器是有源型 | 中 | §7 第 3 项，动手前先验 |
| 键盘实为 I2C 编码型，改变拓扑 | **高** | §7 第 5 项，动手前先验 |
| 无离线成长，玩家觉得"关机就白养" | 低 | 已接受；未来可用 NVS 存时间戳扩展（未排期） |
