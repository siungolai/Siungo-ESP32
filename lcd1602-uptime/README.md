# lcd1602-uptime · LCD1602 (I2C) 通电计时器

上电即开始计时，**每 1 秒**刷新一次屏幕，显示本次通电以来跑了多久。挂在 **1602A 字符液晶 + PCF8574 I2C 背包**上。

> ⚠️ **动手接线前先读第 2 节「5V 供电与电平转换」。**
> 本节是本项目唯一会**烧硬件**的地方，接错不是"不显示"，是慢慢损坏 ESP32 的 IO。

---

## 1. 接线

| 1602 背包排针 | ESP32-S3 | 说明 |
|---|---|---|
| SCL（时钟线） | **GPIO 4** | **必须经电平转换模块**（5V 方案） |
| SDA（数据线） | **GPIO 5** | **必须经电平转换模块**（5V 方案） |
| VCC | **5V**（VIN 或 5V 脚） | 1602 是 5V 器件 |
| GND | GND | 与 ESP32 共地，**地必须连** |

- I2C 引脚编号写在 `src/main.cpp` 顶部的 `PIN_I2C_SCL` / `PIN_I2C_SDA`，换脚只改这两行，不动 `platformio.ini`。
- 沿用同仓库 `uptime-oled` 的 GPIO4/5。这两脚在 ESP32-S3 上都是普通 IO，无 strapping、非 SPI0/1，可安全使用。
- PCF8574 背包地址默认按 **0x27**。少数模块（PCF8574A 芯片）是 **0x3F**，程序启动时若 0x27 不应答会自动换 0x3F 再试一次。

## 2. 5V 供电与电平转换（最重要的一节）

### 为什么 1602 要 5V

1602 的控制器是 HD44780，设计工作电压 5V。用 3.3V 供电时对比度余量很小，
字往往很淡甚至完全看不见——即使把 V0 电位器调到极限。所以本项目按 **5V 供电**设计。

### 为什么 5V 会威胁 ESP32

**ESP32-S3 的 IO 不是 5V 耐受的。** 数据手册规定 IO 的绝对最大输入电压为
`VDD + 0.3V`，3.3V 供电时约 **3.6V**。超过这个值会通过 IO 内部的 ESD 保护二极管
灌电流，属于**慢性损坏**——不会当场冒烟，但 IO 会逐渐劣化甚至永久失效。

### 风险链条

```
背包 VCC 接 5V
   ↓
板上 4.7k 上拉电阻挂到 5V（背包自带的，拆不掉也通常不该拆）
   ↓
SDA/SCL 空闲时被拉到 5V，即总线的 HIGH 电平 = 5V
   ↓
直连 ESP32  →  5V 直接进 IO  →  超压，损坏
```

关键：**上拉电压跟随背包 VCC**。只要背包接 5V，就算 ESP32 侧主动输出的 LOW 没问题，
总线空闲时那两个 5V 高电平照样会顶进 IO。

### 正确接法

**方案 B —— 推荐：背包 5V + 双向电平转换模块**

```
ESP32 3.3V ──┬─ LV 侧参考
             │
GPIO4  ──── TXB0104 / PCA9306 / 4 路 MOSFET 模块 ──── 背包 SCL
GPIO5  ────   (LV=3.3V, HV=5V)                  ──── 背包 SDA
ESP32 GND ──────────────────────────────────────── 背包 GND（必接）
ESP32 5V  ──────────────────────────────────────── 背包 VCC
```

- 市面上"4 路双向电平转换模块"（TXS0108E / TXB0104 / 或 4 个 BSS138 MOSFET 的自制板）都可用。
- I2C 是开漏总线，**MOSFET 型（BSS138）比 TXB0104 更适合**——TXB0104 有方向检测，在开漏总线上偶发振荡。优先选 MOSFET 型或 PCA9306。
- 模块的 LV 接 3.3V、HV 接 5V，两侧地必须共地。

**方案 A —— 不推荐：全 3.3V**

背包 VCC 接 3.3V，SDA/SCL 上拉自然就是 3.3V，可直连、不需要转换模块。
代价是 **1602 在 3.3V 下显影通常很淡**，背光也可能偏暗。
先把 V0 电位器拧到极限试，能看清就用；看不清就必须回到方案 B。

### 怎么确认自己接对了

| 现象 | 判读 |
|---|---|
| 能显示、字迹清晰 | 接线正确 |
| 背光亮但无字符 | E/RS 或数据线问题，或初始化没跑通（见第 6 节） |
| 背光都不亮 | 供电没到背包，查 VCC/GND |
| 完全无应答（串口报 no ACK） | 查 SCL/SDA 是否接反、电平转换模块是否接好、地址是否 0x27 |
| 跑一阵后 IO 失灵 / 发热 | **立即断电**：很可能超压了，检查上拉电压 |

> **强烈建议**：第一次上电前，用万用表量一下背包 SDA/SCL 对 GND 的电压。
> 空闲时应等于电平转换模块 **LV 侧**的 3.3V。若量到 5V，说明转换模块没接对，
> **不要接 ESP32**，先修好。

## 3. 屏幕布局

1602 只有 **2 行 × 16 字符**，版面比 OLED 紧得多，所以只放最有用的两项：

```
┌────────────────┐
│UPTIME #123     │  ← 第 1 行：标题 + 刷新计数
│00:02:03        │  ← 第 2 行：HH:MM:SS 绝对读数
└────────────────┘
```

- **`#123` 刷新计数**：每刷一帧 +1。LCD 掉电后画面还会保留，静止的字**不能**证明刷新在跑；
  这个数字在跳才是"每秒确实更新"的现场证据。
- **满 24 小时自动进位**：第 2 行变成 `1d 02:03:04` 这种写法，天数不会顶掉。
  最长 `365d 23:59:59` = 14 字符，16 列放得下。
- **刷新用定长覆盖**：每行都补空格到 16 列。否则 `TOTAL 10 s` 缩短成 `TOTAL 9 s`
  时，尾部会残留上一帧的字符。

## 5. 串口输出长这样

```
=== lcd1602-uptime ===
I2C: SCL=GPIO4  SDA=GPIO5  100000 Hz
Target: PCF8574 backpack @ 0x27 (LCD1602, 16x2)
LCD init OK at 0x27, refreshing every 1s.
[0] uptime=00:00  refreshes=1
[1] uptime=00:01  refreshes=2
[2] uptime=00:02  refreshes=3
```

初始化失败时会打印 ASCII 版排查清单，并**每 5 秒自动重试**：

```
[ERR] no ACK at 0x27. Trying 0x3F...
[ERR] no ACK at 0x3F either.
Check, in this order:
  1) SCL -> GPIO4, SDA -> GPIO5 (swapped = no ACK)
  ...
[retry] probing LCD again...
```

日志刻意用 ASCII 而不是中文：中文经 UTF-8 送到部分串口工具会变成乱码，
而这条信息恰恰是出故障时唯一能看到的线索。

## 6. 常见问题

| 现象 | 排查 |
|---|---|
| 串口报 `no ACK at 0x27` | ① SCL/SDA 是否接反；② 背包供电与共地；③ **5V 方案下电平转换模块是否接好、LV 侧是否 3.3V**；④ 地址是否为 0x3F。先跑 `tools/i2c-scan` |
| 背光亮但屏幕空白 | ① 初始化序列没跑通（多半是 E 脚或数据线虚接）；② 对比度电位器（背包上的蓝色小旋钮）没调，**先拧它**；③ 5V 供电不足，查电源 |
| 屏上只有一排黑方块 | 控制器上电了但初始化没成功。这是 HD44780 的"未初始化"特征状态，检查 D4–D7 与 E 的接线 |
| 字很淡、斜看才勉强可见 | 典型对比度不足。先拧 V0 电位器；仍不行说明 3.3V 供电（方案 A）撑不住，改方案 B |
| 显示乱码 / 缺笔画 | 4 位模式下 D4–D7 中某根线接错或虚接。逐根确认 P4–P7 到 D4–D7 |
| 第二行内容跑到第一行 | DDRAM 行偏移写错。1602 是"每行 40 字节"，第 2 行从 **0x40** 起（见 `LCD_ROW_OFFSET`） |
| 内容变短后尾部有残字 | 没做定长覆盖。用 `printLine()` 而不是 `print()` |
| 跑一阵后 IO 发热 / 失灵 | **立即断电**：超压。量背包 SDA/SCL 空闲电压，应等于转换模块 LV 侧的 3.3V |

### 关于 `endTransmission()` 的错误码

- 返回 **2** = 该地址**无应答**（器件不在这个地址）→ 查地址跳线；
- 返回 **5** = **超时**（总线根本没法完成事务）→ 直接查物理层接线与电平转换。

看到 5 就不要再纠结地址了。

## 7b. 硬性结论：本项目的故障从未定位到器件（2026-10-14）

本项目的代码与驱动是完整的，但**硬件链路始终没有调通**，因此不计入仓库的可用项目。
排查到最后一轮时做了一次**终极测试**，结果推翻了此前所有判读：

**把 I2C 背包整块拔下来，背光仍然亮、SDA/SCL 仍然读到 HIGH。**

背光由背包上 PCF8574 的 **P7** 脚驱动（见第 9 节的位映射）。器件被拔掉以后，
P7 不可能还在输出——除非**电流根本没经过这块背包**。

因此真正的故障只有两种可能，而**都发生在插接层面，与固件、地址、总线时序全都无关**：

1. 背包的 4 根排针从未真正插入面包板（面包板接触不良 / 插错了行）；
2. 背包与屏体之间的 **16 针并口**（K/A 两排）虚接——A 排负责供电与背光、
   K 排负责 HD44780 的 8 位数据与 RS/RW/E，虚接时"背光有可能亮，但控制器永远收不到指令"。

> ⚠️ **本项目最重要的教训：`背光亮 = 供电到位` 这条判读在本机不成立。**
> 它此前一路把排查引向"PCF8574 坏片"的结论，而实际差了一步插接检查。
> 同理，`float=HIGH` 只能证明**外部上拉电阻存在**，
> **不能证明 SDA/SCL 真的接到了背包**——上拉是无源的，只要 VCC 通就有效，
> 甚至沿着一根没插进去的排针旁的杂散通路都可能读到高。

**下次要做的第一步（不需要 ESP32，万用表即可）**：

| 步骤 | 量什么 | 期望 |
|---|---|---|
| 1 | 屏体排针 ↔ 背包排针 的同名脚通断（VCC、GND、SDA、SCL，以及 16 针并口每一针） | **全部导通**（< 几欧） |
| 2 | 背包 VCC ↔ GND 的静态电阻 | 不为 0（确认无短路） |
| 3 | 都确认后，再上电跑 `tools/i2c-scan` | 0x27 或 0x3F 应答 |

在步骤 1 通过之前，改地址、改时序、改固件全是无效劳动。

## 8. 计时为什么用 `millis()`

需求是"显示通电时间"，精度要求 1 秒级：

- `millis()` 就是**自上电起**的单调计数（48 位累加，跑几十年不溢出），语义上正好等于"通电时间"，不需要额外维护起点；
- 刷新判定用 `now - lastRefresh >= 1000`，**非阻塞**，没有 `delay(1000)`。将来加按键、传感器不用重构主循环；
- 刷新时间戳是 `lastRefresh += 1000` 而不是 `= now`，避免某次刷新被 I2C 拖长后误差长期累积。

> ⚠️ ESP32 进**深度睡眠**时 `millis()` 会停走，醒来后计时不包含睡眠时间。
> 本示例不涉及低功耗深睡。若要"跨重启/跨断电累计"，需要 RTC 内存或 NVS，是另一回事。

## 9. 驱动实现说明

`src/lcd1602_i2c.cpp` + `src/lcd1602_i2c.h` 是**裸驱实现**（约 200 行），不依赖
`LiquidCrystal_I2C` / `LiquidCrystal_PCF8574`：

- 本任务只需"定位光标 + 写两行文本"，裸驱足够；
- HD44780 的时序要求（E 脉冲 450ns、清屏 1.52ms、初始化 4.5ms）直接写在代码里，排查时看得见；
- 零第三方依赖，风格与同仓库 `uptime-oled` 的 SSD1306 裸驱一致。

### PCF8574 的位映射

| 位 | 接到 LCD | 含义 |
|---|---|---|
| P0 | RS | 0=命令 1=数据 |
| P1 | RW | 恒 0（只写不读） |
| P2 | E | 使能脉冲 |
| P3 | 背光 | 1=开 |
| P4–P7 | D4–D7 | 数据高 4 位 |

### 一个 I2C 事务写完两个 nibble

HD44780 用 4 位模式，一个字节要拆成高/低两个 nibble，每个 nibble 都要打一次 E 脉冲。
教科书写法是"拉高 E"和"拉低 E"各做一次 I2C 传输，一个字节 4 次事务。

PCF8574 允许在**一次** `beginTransmission`/`endTransmission` 之间连续写多个字节，
按顺序依次锁存。所以本驱动把 4 个状态字节一次推出去：

```
data|E=1  →  data|E=0  →  data2|E=1  →  data2|E=0
```

这样写一个字节只要 **1 次** I2C 事务。整屏 32 字符从 128 次事务降到 **32 次**。
时序依然满足 datasheet：状态之间隔着 I2C 字节传输时间（100kHz 下约 90µs），
远大于 E 脉冲所需的 450ns。

参考实现对照：`mathertel/LiquidCrystal_PCF8574` 的 `_writeNibble()`
正是把 enable 高/低两次 `write()` 放进同一次 `beginTransmission` 里。

### 影子寄存器

PCF8574 是"写全 8 位"的器件，**没有位操作、也没法读改写**。
每次写都是覆盖全部 8 位，所以 RS/E/背光的状态必须在本地用 `shadow_` 记住，
写 nibble 时一起拼出去。背光切换就是直接改 `shadow_` 的 P3 再整体写一次。

## 10. 与 `uptime-oled` 的关系

两个项目定位相同（都显示通电时间），差别在屏幕：

| | `uptime-oled` | `lcd1602-uptime`（本项目） |
|---|---|---|
| 屏幕 | SSD1306 128×64 图形 OLED | HD44780 16×2 字符 LCD |
| 接口芯片 | 屏自带 I2C 控制器 | **PCF8574 背包**（外挂转换） |
| 供电 | 3.3V | **5V** |
| 电平转换 | 不需要 | **需要**（方案 B） |
| 可显示内容 | 任意像素、大字号、进度条 | 只有字符，2 行 × 16 列 |
| 驱动 | `ssd1306_i2c.cpp` + 字库 | `lcd1602_i2c.cpp` |
| I2C 速率 | 400 kHz | 100 kHz（PCF8574 标称上限） |

两套驱动**完全独立、不能互换**：协议、显存模型、寻址方式都不一样。
共同点是计时逻辑与刷新节拍写法一致，方便对照。
