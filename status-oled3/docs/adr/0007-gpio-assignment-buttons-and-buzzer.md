# 7. 引脚分配：按钮 ×2 + 蜂鸣器占用 GPIO 6 / 7 / 21

日期：2026-10-15（2026-10-16 按 bench 实测接线订正；2026-10-21 按 datasheet v2.2 订正 strapping 脚的事实错误，**脚位结论不变**）

## 状态

已接受（2026-10-16 修订：结论由 GPIO 10 / 11 / 12 改为 **GPIO 6 / 7 / 21**，修订理由见「背景」末段）

## 背景

除三块屏（PCA9548A 上游 **SDA=GPIO5 / SCL=GPIO4**，2026-10-17 实测，见 [`../../../HARDWARE.md`](../../../HARDWARE.md) §4.5）之外，本项目还有三个数字 IO 器件：**两个轻触按钮**（按钮 A 翻页、按钮 B 换聚焦屏，见 [ADR-0001](0001-three-screen-role-split.md)）与**一个有源蜂鸣器**（见 [ADR-0003](0003-active-buzzer-on-off-encoding.md)）。

[`../../../HARDWARE.md`](../../../HARDWARE.md) §1.2 的 GPIO 表里，按钮与蜂鸣器是**零记录**——本机从未用过数字输入或蜂鸣器，没有任何先例可循。可用的脚位池按 §1.2 核定：

| 排除 | 原因 |
|---|---|
| GPIO 1 / 2 | 实测 I2C 全段超时（§6.1），且语义上留给 I2C |
| GPIO 4 / 5 | **本项目的 I2C 上游**（PCA9548A SDA/SCL，2026-10-16 实测接 4/5） |
| GPIO 8 / 9 | `pet-oled3` 初版策划案的 I2C 上游建议值；**2026-10-21 该项目已与本项目硬件对齐**（SDA=GPIO5 / SCL=GPIO4），GPIO 8 改接 PCA9548A RST，8/9 均无归属 |
| GPIO 19 / 20 | 原生 USB D+/D-，占用即失去串口下载（§1.1） |
| GPIO 26–32 | 封装内 Flash/PSRAM（SPI0/1） |
| GPIO 33–37 | OPI PSRAM 8 线高位数据 |
| GPIO 38 | `pet-oled3` 初版规划中的编码器按键脚；**2026-10-21 编码器取消后该脚空闲**，保留为该项目的第三键备位 |
| GPIO 39–42 | JTAG（MTCK=GPIO39 / MTDO=GPIO40 / **MTDI=GPIO41** / MTMS=GPIO42） |
| GPIO 43 / 44 | UART0 |
| GPIO 45 / 46 | strapping 脚（见下方「2026-10-21 事实订正」：datasheet v2.2 的 strapping 脚只有 GPIO 0 / 3 / 45 / 46） |
| GPIO 48 | 板载 WS2812 |

剩下的候选是 GPIO 0 / 3（strapping，排除）、GPIO 6 / 7、GPIO 10–18、GPIO 21、GPIO 47、GPIO 12。选哪三个，需要一条能同时满足「本项目自洽」与「仓库跨项目可读」的原则。

> 📌 **2026-10-21 事实订正（datasheet v2.2 核实）**：本 ADR 旧版把 **GPIO 12 写成「MTDI strapping 脚」**——这是**双重事实错误**，现已全面清除：
>
> 1. **ESP32-S3 的 strapping 脚只有 GPIO 0 / 3 / 45 / 46**（datasheet v2.2 §2.3.4，列在 Priority 3 清单下）。§3 Boot Configurations 给出各自作用：GPIO0 + GPIO46 = chip boot mode、GPIO45 = VDD_SPI 电压档位、GPIO46 = ROM 消息打印、GPIO3 = JTAG 信号源。
> 2. **MTDI = GPIO 41**，不是 GPIO 12。JTAG 四线完整映射：MTCK=GPIO39、MTDO=GPIO40、**MTDI=GPIO41**、MTMS=GPIO42。
> 3. **GPIO 12 在 datasheet 里是 P2（可自由使用、无限制）**，复用功能 FSPIIO6 / SUBSPICLK。
>
> **影响范围**：**脚位结论完全不变**（按钮 A=GPIO6、按钮 B=GPIO7、蜂鸣器=GPIO21），因为这三个脚本来就不是 strapping 脚，且与 bench 实物一致。但**理由链要重写**——见下方各处的「2026-10-21 订正」块。

> **2026-10-16 修订背景**：用户 bench 实际上板后回报接线——「4\5我接的是PCA9548A；6和7分别接了一个轻触开关；21接了一个有源蜂鸣器」。原决策是 GPIO 10 / 11 / 12。修订采纳实测接线，因为：① 三个脚位都不在 §1.2 禁区表内，无冲突 ② 改固件只是三个常量（`src/config.h`），代价为零 ③ 保持与 bench 实物一致，比保持文档自洽更重要 ④ GPIO 21 优于 GPIO 12 的地方在于「已实测接在 21 上可用」，不是「GPIO 12 不能用」。
>
> > 📌 **2026-10-21 订正**：旧版在此处写「原决策的 GPIO 12 是 MTDI strapping 脚，用它驱动蜂鸣器在上电瞬间有隐患」——**该理由不成立**（见上方事实订正）。真实情况是：GPIO 12 本身可用，但 bench 实物已经接在 21，**没有理由为了改文档而改接线**。旧版把一个「碰巧对的事实」记成了「原理性禁忌」，会在将来误导别人绕路，也让 §1.2 的 GPIO 表多出一行假禁区。

## 考虑的方案

### 方案 A：按钮 A = GPIO6、按钮 B = GPIO7、蜂鸣器 = GPIO21 —— 采纳（2026-10-16 修订后的结论）

按钮用 `INPUT_PULLUP`（按下接地为低电平），蜂鸣器用推挽输出。

**采纳理由**：

1. **三个脚位都不在 §1.2 禁区表内**，无冲突：GPIO 6 / 7 非 strapping、非 SPI、非 USB、非 JTAG；GPIO 21 是普通 IO
2. **与 bench 实物一致**：用户已按此接线并上板，固件 `src/config.h` 的三个常量跟着订正即可，无返工
3. **GPIO 7 的双角色已被 §1.2 记录**：它与 `dht11-oled` 的 DHT11 数据脚二选一（不可同插），该行本来就是为这种情况写的，不新增冲突
4. **保留 GPIO 10–18 连号段**：`pet-oled3` 初版的 4x4 键盘行线规划（10–13）因此不受影响，仓库 GPIO 表保持单一解读

> 📌 **2026-10-21 订正**：旧版第 1 条是「避开 GPIO 12（MTDI strapping 脚）——这是本次修订的**主要收益**」。**该条已删除**：datasheet v2.2 证明 GPIO 12 不是 strapping 脚、MTDI 是 GPIO 41。真实的采纳理由是上面第 1–3 条（无禁区冲突 + 与实物一致 + 改动面只有三个常量）。旧版把「实测接线碰巧落在这三个脚上」包装成「原理性禁忌带来的收益」，属于**结论对但理由错**——本次订正只修理由，不动结论。
>
> 📌 **2026-10-21 订正（第 4 条）**：第 4 条的理由已随 `pet-oled3` 取消键盘而作废（见 [`../../../pet-oled3/docs/adr/0007-two-buttons-only-input.md`](../../../pet-oled3/docs/adr/0007-two-buttons-only-input.md)）。`pet-oled3` 现与本项目硬件完全对齐，连号段不再被它需要——但**脚位结论本身不变**（按钮 6/7、蜂鸣器 21）。

### 方案 A'：按钮 A = GPIO10、按钮 B = GPIO11、蜂鸣器 = GPIO12 —— 原决策，已被取代

三个脚位连号，落在 GPIO 10–18 这一段的低端。**原采纳理由**（连号省接线排查、与 `pet-oled3` 策划案 §3.5 的「普通 IO」声明一致、避开全部 strapping、避开 GPIO 38）在其自身框架内成立。2026-10-16 修订时，本 ADR 曾把 GPIO 12 误判为「MTDI strapping 脚」并据此否定本方案——**该判据是错的**（datasheet v2.2：strapping 脚只有 GPIO 0/3/45/46，MTDI=GPIO41，GPIO 12 是 P2 普通 IO）。本方案被取代的真实理由是**bench 实物已经接在 6/7/21**。

**取代理由**：见方案 A 第 2 条（与 bench 实物一致）。此处保留原文是为了记录「曾经把 GPIO 12 误判为 strapping 脚」这个错误，避免将来重新提出。

**否决理由**：GPIO 38 原是 `pet-oled3` 规划中的编码器按键脚。本项目不用编码器，占用它在技术上成立，但会让 HARDWARE.md §1.2 那一行从「规划中」变成「被 status-oled3 占了」，而 `pet-oled3` 一旦真的开工就要改脚——这是用本项目的便利换另一个项目的返工。

> 📌 **2026-10-21 订正**：`pet-oled3` 已取消编码器，GPIO 38 现为**空闲脚**并保留为该项目的第三键备位。**本方案的否决理由因此只剩一半成立**（"避免两个项目抢同一脚"的返工顾虑仍在），脚位结论本身不变。

### 方案 C：按钮 A = GPIO47、按钮 B = GPIO6、蜂鸣器 = GPIO21

**否决理由**：GPIO 47 紧邻 strapping 脚 GPIO 45/46，虽然 47 本身不是 strapping，但「贴着 strapping 脚」在排查上电异常时会增加无谓的怀疑面；GPIO 6 无任何先例。换来的是「保留 GPIO 10/11/12 连号段给未来第三个按钮」——但本项目明确只有两个按钮，这个预留没有对应需求。

## 决策

| 器件 | GPIO | 模式 | 有效电平 |
|---|---|---|---|
| 按钮 A（聚焦屏翻页） | **GPIO 6** | `INPUT_PULLUP` | 低（按下接地） |
| 按钮 B（切换聚焦屏） | **GPIO 7** | `INPUT_PULLUP` | 低（按下接地） |
| 有源蜂鸣器 | **GPIO 21** | `OUTPUT` 推挽 | 高（通） |

按钮的消抖在软件里做（`millis()` 时间窗 + 状态机），不依赖外部 RC——轻触按钮的抖动窗口通常在 5–20 ms，软件消抖足够，且省两个电阻。

蜂鸣器不接 PWM（见 [ADR-0003](0003-active-buzzer-on-off-encoding.md)），GPIO 21 只做通断，振荡由蜂鸣器内部电路完成。注意有源蜂鸣器的电流：ESP32-S3 单脚默认驱动强度 20 mA（[`../../../HARDWARE.md`](../../../HARDWARE.md) §1.2 注），有源蜂鸣器典型 20–30 mA，若实测音量为可接受则直驱；若音小或脚烫，加一只 NPN 三极管驱动——那是实现期的事，不改本决策的脚位。

## 后果

### 正面

- **完全避开 strapping 脚**（GPIO 0 / 3 / 45 / 46），上电时序不可能干扰下载模式与 flash 电压判定
- GPIO 10–18 连号段整体未被占用，留给未来扩展
- 与 bench 实物一致，`src/config.h` 的三个常量（`PIN_BUTTON_PAGE=6` / `PIN_BUTTON_FOCUS=7` / `PIN_BUZZER=21`）即全部改动面

### 负面 / 需承担的成本

1. **三个器件分散在 6/7/21**，不再是连号：万用表查线时要对照表格而不是「相邻三针」。代价很小（三根线）
2. **GPIO 7 与 `dht11-oled` 的 DHT11 数据脚二选一**：两个项目不能同时上电。§1.2 已有该行记录，用「项目」列区分即可
3. **蜂鸣器直驱的电流风险**：见上文，若音小/发热则加三极管，属于可预期的迭代

## 备注

- 本决策只定脚位，不定电气细节（上拉阻值、是否需要外部下拉、蜂鸣器是否加三极管）——那些在 M0 bringup 时实测确认
- 若实测发现 GPIO 6 / 7 有异常（例如与 USB 串口有干扰），在同一段内平移到 GPIO 10 / 13 / 14 的代价只是改三个常量
- **教训**：本 ADR 旧版把 GPIO 12 误记为「MTDI strapping 脚」，而 datasheet v2.2 明确 strapping 脚只有 GPIO 0/3/45/46、MTDI 是 GPIO 41。**教训本身仍然成立但结论要改写**：错误不在「§1.2 的 GPIO 表漏标了 12」，而在「没人核对过 datasheet 就把 12 写进了禁区表」。§1.2 的 GPIO 表已按 datasheet v2.2 订正（GPIO 12 归为普通 IO，strapping 脚行只留 0/3/45/46），见 [§1.2](#12-gpio-资源与占用约束)
- **元教训**：写「某脚是 strapping / 某某用途」这类**规格性断言**时，必须能指到 datasheet 的具体章节，否则只能写成「未在本机核实」。本 ADR 曾用一条查证成本极低、收益极高（避免一次 36 小时级别的排查）却没做的核对，换来一个假禁区
