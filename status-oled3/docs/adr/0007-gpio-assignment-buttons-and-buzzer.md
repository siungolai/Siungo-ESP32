# 7. 引脚分配：按钮 ×2 + 蜂鸣器占用 GPIO 10 / 11 / 12

日期：2026-10-15

## 状态

已接受

## 背景

除三块屏（PCA9548A 上游 SDA=GPIO8 / SCL=GPIO9，见 [`../pet-oled3/docs/adr/0001-use-pca9548a-for-three-displays.md`](../pet-oled3/docs/adr/0001-use-pca9548a-for-three-displays.md)）之外，本项目还有三个数字 IO 器件：**两个轻触按钮**（按钮 A 翻页、按钮 B 换聚焦屏，见 [ADR-0001](0001-three-screen-role-split.md)）与**一个有源蜂鸣器**（见 [ADR-0003](0003-active-buzzer-on-off-encoding.md)）。

[`../../HARDWARE.md`](../../HARDWARE.md) §1.2 的 GPIO 表里，按钮与蜂鸣器是**零记录**——本机从未用过数字输入或蜂鸣器，没有任何先例可循。可用的脚位池按 §1.2 核定：

| 排除 | 原因 |
|---|---|
| GPIO 1 / 2 | 实测 I2C 全段超时（§6.1），且语义上留给 I2C |
| GPIO 4 / 5 | 既有项目（`uptime-oled` / `clock-oled`）的 I2C SCL/SDA，本项目虽不用，但占用会污染仓库的接线图 |
| GPIO 6 / 7 | GPIO 7 是 `dht11-oled` 的数据脚；GPIO 6 未被占用但也无使用先例 |
| GPIO 8 / 9 | 本项目 I2C 上游（SDA / SCL） |
| GPIO 19 / 20 | 原生 USB D+/D-，占用即失去串口下载（§1.1） |
| GPIO 26–32 | 封装内 Flash/PSRAM（SPI0/1） |
| GPIO 33–37 | OPI PSRAM 8 线高位数据 |
| GPIO 38 | `pet-oled3` 规划中的编码器按键脚 |
| GPIO 39–42 | JTAG |
| GPIO 43 / 44 | UART0 |
| GPIO 45 / 46 | strapping 脚 |
| GPIO 48 | 板载 WS2812 |

剩下的候选是 GPIO 0 / 3（strapping，排除）、GPIO 10–18、GPIO 21、GPIO 47。选哪三个，需要一条能同时满足「本项目自洽」与「仓库跨项目可读」的原则。

## 考虑的方案

### 方案 A：按钮 A = GPIO10、按钮 B = GPIO11、蜂鸣器 = GPIO12 —— 采纳

三个脚位连号，落在 GPIO 10–18 这一段的低端。按钮用 `INPUT_PULLUP`（按下接地为低电平），蜂鸣器用推挽输出。

**采纳理由**：

1. **连号 = 接线与排查都省事**：三根线插在相邻三针上，万用表量错了能立刻发现；反过来若分散在 10/21/47，查线成本翻倍
2. **GPIO 10–18 与 `pet-oled3` 规划一致**：策划案 §3.5 把 GPIO 10–18 / 21 / 38 标为「建议值，全部普通 IO」。沿用它意味着两个项目的接线图不会互相矛盾，HARDWARE.md 的 GPIO 表也只会有一种解读
3. **避开全部 strapping 脚**（GPIO 0 / 3 / 45 / 46），上电时序不影响下载模式
4. **避开 GPIO 38**：虽然 §1.2 把它记作「规划中：编码器按键」，占用它会让 `pet-oled3` 的文档失效——本项目没有编码器，无需这个脚

### 方案 B：按钮 A = GPIO10、按钮 B = GPIO11、蜂鸣器 = GPIO38

**否决理由**：GPIO 38 是 `pet-oled3` 规划中的编码器按键脚。本项目不用编码器，占用它在技术上成立，但会让 HARDWARE.md §1.2 那一行从「规划中」变成「被 status-oled3 占了」，而 `pet-oled3` 一旦真的开工就要改脚——这是用本项目的便利换另一个项目的返工。

### 方案 C：按钮 A = GPIO47、按钮 B = GPIO6、蜂鸣器 = GPIO21

**否决理由**：GPIO 47 紧邻 strapping 脚 GPIO 45/46，虽然 47 本身不是 strapping，但「贴着 strapping 脚」在排查上电异常时会增加无谓的怀疑面；GPIO 6 无任何先例。换来的是「保留 GPIO 10/11/12 连号段给未来第三个按钮」——但本项目明确只有两个按钮，这个预留没有对应需求。

## 决策

| 器件 | GPIO | 模式 | 有效电平 |
|---|---|---|---|
| 按钮 A（聚焦屏翻页） | **GPIO 10** | `INPUT_PULLUP` | 低（按下接地） |
| 按钮 B（切换聚焦屏） | **GPIO 11** | `INPUT_PULLUP` | 低（按下接地） |
| 有源蜂鸣器 | **GPIO 12** | `OUTPUT` 推挽 | 高（通） |

按钮的消抖在软件里做（`millis()` 时间窗 + 状态机），不依赖外部 RC——轻触按钮的抖动窗口通常在 5–20 ms，软件消抖足够，且省两个电阻。

蜂鸣器不接 PWM（见 [ADR-0003](0003-active-buzzer-on-off-encoding.md)），GPIO 12 只做通断，振荡由蜂鸣器内部电路完成。注意有源蜂鸣器的电流：ESP32-S3 单脚默认驱动强度 20 mA（[`../../HARDWARE.md`](../../HARDWARE.md) §1.2 注），有源蜂鸣器典型 20–30 mA，若实测音量为可接受则直驱；若音小或脚烫，加一只 NPN 三极管驱动——那是实现期的事，不改本决策的脚位。

## 后果

### 正面

- 三个器件三根相邻线，硬件接线图一张即可，排查时不用翻 HARDWARE.md
- 全部落在 `pet-oled3` 已声明为「普通 IO」的段内，仓库 GPIO 表保持单一解读
- 与 GPIO 8/9 的 I2C 上游物理上分开（10/11/12 vs 8/9），接线时不容易误插

### 负面 / 需承担的成本

1. **GPIO 10–18 段被本项目占掉 3 个**：若将来本项目要扩第三个按钮，需要重新规划——但 [ADR-0001](0001-three-screen-role-split.md) 明确只有两个按钮，该代价不兑现
2. **蜂鸣器直驱的电流风险**：见上文，若音小/发热则加三极管，属于可预期的迭代
3. **`pet-oled3` 的 GPIO 10–18 段原本预留给 4x4 键盘行线**：两个项目不可能同时上电，但同版本 HARDWARE.md 里这段会出现「本项目键盘行 1–3」与「status-oled3 按钮+蜂鸣器」两种规划。用表格里的「项目」列区分即可，不构成冲突

## 备注

- 本决策只定脚位，不定电气细节（上拉阻值、是否需要外部下拉、蜂鸣器是否加三极管）——那些在 M0 bringup 时实测确认
- 若 M0 实测发现 GPIO 10/11 有异常（例如与 USB 串口有干扰），优先在同一段内平移到 GPIO 13/14/15，而不是跳出 10–18 段——平移的代价只是改三个常量
