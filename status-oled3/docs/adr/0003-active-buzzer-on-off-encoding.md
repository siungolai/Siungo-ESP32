# 3. 有源蜂鸣器：只用通断时长编码，不出音阶

日期：2026-10-15

## 状态

已接受

## 背景

用户实测手上的蜂鸣器为**有源型**：两端直接通 3.3V 即响。有源蜂鸣器内部自带振荡电路，**只能发出一个固定频率的声音**，无法通过 PWM 改变音高，也出不了旋律。

`pet-oled3` 初版策划案规划的是**无源**压电蜂鸣器 + LEDC `ledcWriteTone` 出音阶旋律（四种音效：按键点击、数值告警、升级上行旋律、低沉拒绝音）。该方案在这颗有源蜂鸣器上**不成立**。

> 📌 **2026-10-21**：`pet-oled3` 已按用户决策与本项目硬件对齐，其蜂鸣器**同为有源型**，音效设计已全部退化为通断节奏编码——见 [`../../../pet-oled3/docs/adr/0006-hardware-interface-aligned-with-status-oled3.md`](../../../pet-oled3/docs/adr/0006-hardware-interface-aligned-with-status-oled3.md)。本 ADR 的结论对两个项目都成立。
>
> 📌 **章节号订正（2026-10-21）**：本 ADR 原文引用的「`pet-oled3` 初版策划案 §5.5」是**初版**的章节号；`pet-oled3` 现行策划案里该内容已挪到 **§4.4（蜂鸣器节奏表）**，并保留了「原设计的四种音效在本硬件上无法原样实现」的说明块。

## 考虑的方案

### 方案 A：只用通断时长编码（短响 / 长响 / 连续短响）—— 采纳

一个 GPIO 通断即可，不追求音高变化，用**节奏**区分事件类型。

**采纳理由**：

1. **硬件只能这样**：有源模块的频率固定，任何 PWM 技巧都得不到稳定音高
2. **实现为零**：`digitalWrite` + `millis()` 非阻塞，不需要 LEDC、不需要占一个定时器通道
3. **本项目的事件种类本就有限**：新邮件、服务器掉线、设备自身断网，三类足以用节奏区分

### 方案 B：外加方波信号"调制"有源蜂鸣器

**否决理由**：有源模块内部已有振荡器，外加 GPIO 信号只能起到通断/调制的效果，得不到可辨识的不同音高，反而引入电流噪声与不确定性。

### 方案 C：换购无源压电蜂鸣器

**不否决，记录为可选硬件升级**：无源蜂鸣器成本极低，换上即可回到初版的音阶方案（含上行旋律）。但**不阻塞本项目**——方案 A 已能满足通知需求，无源是增强项而非前置条件。（`pet-oled3` 2026-10-21 已与本项目硬件对齐，**同样按有源型处理**，不打算换件。）

## 决策

蜂鸣器通知 = **时长模式编码**，一个 GPIO 通断实现，非阻塞。具体映射（初版，待 M1 调）：

| 事件 | 节奏 |
|---|---|
| 有新未读邮件 | 短响 1 次 |
| 服务器数据停更超时（掉线判定） | 连续短响 3 次 |
| ESP32 自身 WiFi 断开 | 长响 1 次 |
| 按钮反馈（**有效操作与空操作都响**） | 极短响 1 次 |

蜂鸣器用 GPIO 21（见 [ADR-0007](0007-gpio-assignment-buttons-and-buzzer.md)），推挽输出、只做通断。

### 按钮反馈：两个按钮都要响（2026-10-17 修订）

初版只写了「按钮空操作 = 极短响 1 次（可选）」，M0 实现时只给按钮 A 的空操作路径接了提示音。上板实测暴露了不一致：**按 A 有声音（但只在它什么都没做时响），按 B 完全没声音**——B 明明切换了聚焦屏、屏幕上有可见变化，却是静音的。用户回报此问题后修订。

修订后：**两个按钮的每一次被接受的短按都极短响 1 次**，不论它是否改变了屏幕内容。

**采纳理由**：
1. **一致性**：两个键行为对称，用户不需要记住「哪个键会响」
2. **可区分性**：极短响（20ms）与新邮件的短响（80ms）时长差 4 倍，超过本文件备注里「≥ 3 倍」的判据；与停更的三连响在计数上不同、与 WiFi 断的长响（400ms）在时长上差 20 倍
3. **零成本**：`patternButtonEmpty()` 是阻塞式 `beep()`，20ms 的占用对 1s 刷新节拍无影响

## 后果

### 正面

- 驱动代码约 20 行，无第三方依赖、无 LEDC 配置
- 与三块屏的刷新完全解耦（`millis()` 非阻塞，不会拖慢总线）

### 负面 / 需承担的成本

1. **表达力受限**：只能靠节奏区分，事件种类上限约 4 种（再多就难以记忆、难以在嘈杂环境分辨）
2. **固定频率可能与环境音接近**，安静房间里辨识度尚可，嘈杂环境不行
3. **若换无源蜂鸣器**，音效表与驱动都要重写（预留这个改动，但不提前实现）

## 备注

- 有源/无源的判别方法：直接给蜂鸣器两端通 3.3V，**响 = 有源，不响 = 无源**。此方法已由用户实测，结论为有源
- 若采用"极短响表示空操作"，需注意与"短响表示新邮件"在节奏上的可区分度（时长差建议 ≥ 3 倍）
- 蜂鸣器 GPIO 从初版的 GPIO12 改到 GPIO21：按 bench 实测接线订正（2026-10-16）。**注**：旧版把理由记为「GPIO12 是 MTDI strapping 脚」是错的——datasheet v2.2 核实 strapping 脚只有 GPIO 0/3/45/46，MTDI 是 GPIO41，GPIO12 是 P2 普通 IO（见 [ADR-0007](0007-gpio-assignment-buttons-and-buzzer.md)）
- 字模方向自检（`fontDirProbe()`，`ssd1306_i2c.cpp` 的 `begin()` 末尾）2026-10-17 上板实测通过：三块屏上的字无上下镜像，`0xC8`（COM 扫描反向）保持正确，无需改 `0xC0`
