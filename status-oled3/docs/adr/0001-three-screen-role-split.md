# 1. 三屏按「本机 / 服务器 / 邮箱」分工，外加一层聚焦屏翻页

日期：2026-10-15

## 状态

已接受

## 背景

本项目三块 128×64 屏承载三类互不相关的信息：**ESP32 自身状态**、**阿里云服务器状态**、**若干邮箱状态**。同时用户要求「两个按钮进行功能的切换」。这两句话有张力——三块屏已经各自对应一类信息，「功能切换」到底切什么，必须先钉死，否则界面层与输入层都无法设计。

本项目沿用 `pet-oled3` 的三屏拓扑（PCA9548A 单总线、三通道、一次只选通一路，见 [`../pet-oled3/docs/adr/0001-use-pca9548a-for-three-displays.md`](../pet-oled3/docs/adr/0001-use-pca9548a-for-three-displays.md) 与 [`0002-single-channel-sequential-refresh.md`](../pet-oled3/docs/adr/0002-single-channel-sequential-refresh.md)），屏的物理分配与刷新调度不受本文影响。

## 考虑的方案

### 方案 A：每屏一个固定主题，按钮在主题内翻页 —— 采纳

三块屏职责固定为 **ESP32 状态屏（通道 0）/ 服务器屏（通道 1）/ 邮箱屏（通道 2）**，任何时候三块屏同时各显示一类信息。「功能切换」落在两个更细的粒度上：

- **按钮 A 短按**：聚焦屏翻到下一页（循环回第一页）
- **按钮 B 短按**：切换聚焦屏（通道 0 → 1 → 2 → 0），被聚焦的屏标题栏反色标记

**采纳理由**：

1. **三块屏各管一类信息，一眼看完，不需要切换就能看到全部主题**——这是三屏硬件相对于单屏的唯一优势，放弃它就是浪费两块屏
2. **服务器指标一屏放不下**（CPU / 内存 / 磁盘 / 网络四项 + 服务探活），翻页是刚需；邮箱未读数通常一屏列得下，不需要翻页——按钮 A 的落点因此主要服务于服务器屏
3. **两个按钮语义不重叠**（一个翻页、一个换对象），都不需要长按，也不产生"短按长按同一键"的记忆负担
4. **「功能切换」不必解释成"换功能模块"**：翻页与换聚焦屏已经是用户心智模型里最小的两个切换动作

### 方案 B：三屏当作三页，按钮整体翻页

一次只有一块屏有内容，两块黑屏。

**否决理由**：直接把三屏退化成单屏，硬件优势归零；且「功能切换」的语义变成"切页面"，与用户"三屏幕展示三类状态"的原始描述矛盾。

### 方案 C：一块屏固定，另两块可切换主题

**否决理由**：邮箱通常是三者中信息量最小的（一列未读数），固定它是浪费；而"哪一块固定"没有原则可依，只会得到一个任意的分工。相比之下方案 A 的三块都有明确且等量的信息职责。

## 决策

三块屏固定分工：**ESP32 状态屏（通道 0）/ 服务器屏（通道 1）/ 邮箱屏（通道 2）**，全部保持出厂 0x3C 地址。

输入映射：**按钮 A 短按 = 聚焦屏翻页（循环）**，**按钮 B 短按 = 切换聚焦屏（循环）**。聚焦屏标题栏反色。上电默认聚焦 ESP32 状态屏。

## 后果

### 正面

- 三类信息同时可见，符合"三屏"的硬件立意
- 按钮只需区分短按，交互层最简单
- 翻页与换焦点两个动作可以独立扩展（未来服务器屏加页、邮箱屏加页，互不影响）

### 负面 / 需承担的成本

1. **「聚焦屏」是一个全局隐式状态**：用户必须知道当前焦点在哪块屏上，否则按按钮 A 不知道会翻哪块。用标题栏反色补偿，但这仍是一个需要学习的概念
2. **邮箱屏可能长期没有翻页需求**，按钮 A 在邮箱屏上成为空操作（按下去无反馈）。需要决定：空操作时是否给一个极短的"无效"提示音（有源蜂鸣器见 [ADR-0003](0003-active-buzzer-on-off-encoding.md)）
3. **每块屏需要自己的页模型**（页数、当前页号、每页绘制函数），比"一屏一函数"多一点结构

## 备注

- 若未来邮箱数量增长到一屏列不下（超过约 6 个），邮箱屏同样需要翻页，届时按钮 A 的语义自然扩展到两块屏，本决策不需修改
- 「聚焦」只决定按钮的落点，**不影响三块屏各自的数据刷新**——数据刷新仍按 [ADR-0004](0004-fixed-server-polling-and-staleness.md) 的节奏独立进行
